## 阶段 0 · 从零到能聊（基线 `4f603a5`）

插件骨架、四层状态（情绪/心境/关系/人格）、会遗忘的记忆卡、自检面板、OneBot 11 接入，
以及在真机上把 SnowLuma 连通（端口、token、代理、Defender 误删）。

**这个阶段最大的收获不是功能，是一张故障清单**——见后面「缺陷账本」第 1–8 条。
它们的共同点：**不报错，但功能没生效**。这类故障比崩溃难查十倍。

基线：196 项测试。

## 阶段 2 · 钱（229 → 246，`212a57b`）

起点是「只能自己统计吗」。去 DSH 内部翻过之后，答案是**不**：

- 官方余额接口可用（key 走凭据 seam），实测 200；
- DSH 自带的 token 计量按持久会话日志回放，**称不到我们**（我们是自管循环）；
- 所以：余额查真的，token 自己数，**不编单价**。

实测证据：一小时内余额 13.23 → 13.08，那 0.15 是宿主花的。

## 阶段 3 · 她刚才不在（246 → 255，`c18f19b`）

一个时间戳 + 三道人话闸（≥30 分钟才说、开机两小时有效、时钟拨回不说）。

顺手补了一个没被问但更常见的洞：**睡眠**。心跳间隔超过 20 分钟 = 进程被冻住 = 她那段时间同样不存在。
关机和睡眠在她这边是同一件事，所以走同一句话。

## 阶段 7 · 她终于能先开口了（11-07，341 项测试）

用户的一句原话是「他完全不能自主的找我」。查下来不是没做，是**三层 bug 叠在一起**：

1. `proactive.enabled` 从装上那天（10-28）起就是 `false`，一次没开过；
2. 闸门里有 `if (lastBotAt > lastUserAt) return no('上一条是我说的，等他说')`，
   而**每轮对话都以她说话结束**——这一条等于「除非我上次没回他，否则永远不许先开口」；
3. 那句 `【系统提醒·不是他说的】` 是走 `session.prompt()` 发的，会以 **user 角色**进 `history`。
   于是它既住进了她的记忆（将来她会以为是他说的），又把她自己的提醒算成「他刚说话」，一次之后就自锁。

照 [dsh-heartbeat-inner](https://github.com/zy666946/dsh-heartbeat-inner) 重做触发：
期待时间跟着对话走（她说完一轮 → 按他平时回复间隔算 → 深夜推到早上八点），到点才自己想一次；
决策输出 JSON（发 / 晚点再想）；连发上限 2 条替代那条死锁；「想」改成一次独立调用，不碰主历史；
真发出去的那句话才用 `session.note()` 记进历史（否则他下一句接上来她不知道自己刚问过什么）。

顺带补了一件更基础的事：**她以前聊天时看不到时间**（只在「决定此刻干什么」时看得到日期）。
上下文第一行现在是 `此时：11月7日 周五 23:47`——没有这一行，期待点根本不可能成立。

调研范围：[dsh-proactive](https://github.com/john-walks-slow/dsh-proactive)（唤醒不等于发言、静默折叠）、
[Kanadego/dsh-heartbeat](https://github.com/Kanadego/dsh-heartbeat)（闸门先于模型、心事匣）、
[dsh-proactive-chat](https://github.com/shuaig22/dsh-proactive-chat)、
[dsh-self](https://github.com/xiaoyeziyinxing/dsh-self)、
[dsh-wife-memory](https://github.com/yxie15022-debug/dsh-wife-memory)。
只借思路，没有抄代码。

同一天后半段补了「她知道外面什么天」和「她能查真事」。一个实测结论值得记：
用搜索接口问「上海现在天气」，它答 19°C 阴；同一时刻 Open-Meteo 的观测是 15.3°C 毛毛雨。
**网页答案本身是滞后的**，所以天气走 Open-Meteo（免密钥），搜索只用来查「网上怎么说」。
Tavily 的 answer 还会冒出英文（哪怕问的是中文），正文又是导航栏乱码——
因此查回来先让她自己压成一句 ≤50 字的中文事实，压不出来就整条不记（「没查到」和「没查」对她是一回事）。

再晚一点又修了一个更基础的时间 bug：11-06 21:44 他抱怨她不主动，11-08 21:04 她说「刚还嫌我不理你」。
原因是 `history` 存了 `at`，拼 `messages` 时只取 `{role, text}`，那 47 小时的空白在她眼里不存在。
现在只在断层处打时间戳（第一条 + 隔半小时以上的那条），压缩的入参和摘要提示词也带上日期。
对照组很能说明问题：她 20:37 独处时想的是「两天没动静」——因为那条路给了小时数，聊天那条路没给。

接着做了「看视频」：借 dsh-see-now 的两条思想（按变化挑帧、多帧拼一张图），ffmpeg 抽帧 + sharp 拼图。

再往后补了一件更基础的事：**她翻得回原话了**。压缩会把原文吃掉，于是她说不出「这句话你是哪天说的」。现在每条真进历史的话都追加到 `transcript-YYYY-MM.jsonl`（按月、只追加），只有他明显在回忆时才去翻，翻出来的是原话 + 时间戳。边界写在设计文档里：只看字面（2-gram）、不是每句都翻、明文留在磁盘上。

再往后是「表情包又读不了」：根因是动图抽帧只给了 sharp 的 `page` 没给 `pages:1`，拿到的是「从这页往下全部」的叠加图——一个 300×11700 的表情包变成 300×8700、1.6MB 的图，四帧发出去请求体 4.5MB，接口 400。现在缩成 320 的 JPEG，四帧共 105KB。顺带把 face 的 id 用 `fetch_sys_faces` 换成名字（「流泪」），不再只是一句「[表情]」。

同一批还修了四个小东西：①「她的当下」输出预算只有 60 token，推理模型吃完就返回空，于是她永远定不下「我此刻在干什么」；②压缩阈值 30/12 → 40/16（她丢细节丢得太快）；③记忆协议加了第 6 条——「有碎片但没下结论」不等于「完全记不清」，别把前者说成后者；④合并转发只留了「[转发]」两个字，现在是 get_forward_msg 把里面每条读出来，并注明「这些话不是他说的」。

中间还补了一个更根本的问题：她其实从没「看见」过图片，只看到另一个模型写的描述。现在原图只在图到达的那一轮跟过去，历史里仍存文字——当场看画面，之后想描述。
第一版用灰度算变化分，真机一测红→绿只有 17 分——「换了一整屏」被判成「没怎么变」；改成逐通道后 128/127，挑出来的正好是切点。

## 决策账本

| 决策 | 理由 | 当时否掉的 |
|---|---|---|
| 事件必须可核对，不做随机事件表 | 随机事件 = 用我们的世界冒充她的世界 | 随机事件表、模拟人生懒推进 |
| 钱只报余额、token 只报计数 | 单价会变，且会把宿主的开销算到她头上 | 按 token × 单价估算 |
| 「当下」挂定时器不挂每句 | 成本 | 每轮问她一次 |
| 遗忘可逆（软删除） | 用户想起时应该能回来 | 忘了就删 |
| 失效显式、可撤销、判定吝啬 | 误杀的代价不可见，矛盾的代价可纠正 | 自动覆盖 |
| 日记/自述由她写 | 主体性；系统代笔等于把她变成被描述的对象 | 系统生成文案 |
| 连发合并 3 秒（原定 5 秒） | 用户改的；3 秒是人打字停顿的量级 | 5 秒 / 30 秒 |
| 先记录评价、不接行为 | 怕她学会讨好 | 让 👍/👎 直接决定人格写入 |

## 缺陷账本

「测试抓到」和「真机/运气抓到」标了出来——后者说明还缺一层测试。

| # | 症状 | 根因 | 谁抓到 |
|---|---|---|---|
| 1 | 插件「装了但半死」 | `inject` 漏 `webServer`，代理一读就抛，后续全静默中断 | 真机 |
| 2 | 从第二轮起「模型调用失败：UNKNOWN」 | assistant 消息缺 `id` + `source` | 真机 |
| 3 | 面板显示 `自动：[object Object]` | provider 返回的是对象，被当字符串用 | 真机 |
| 4 | 填 token 时表单被冲掉 | 面板 10 秒自动刷新 | 用户 |
| 5 | 历史 84 条、压缩 0 次、摘要空 | 压缩请求带了 `temperature`，被某些模型拒绝，而失败被静默吞掉 | 真机 |
| 6 | 没配主人时谁都能聊 | owner 判空是放行 | 自查 |
| 7 | 每天上限在早上 8 点重置 | 日界用了 UTC | 自查 |
| 8 | 任意网页一个 GET 就能让她失忆 | 写操作挂在 GET 上，没有跨站拦截 | 自查 |
| 9 | 补写昨天的日记把今天的事写进去 | 只卡了上界没卡下界 | 测试 |
| 10 | 空答后每条消息烧两次模型 | 没有重试闸 | 测试 |
| 11 | 「比昨天模糊」在隔了四天时是假话 | 基线没验证「昨天」是否真的存在 | 测试 |
| 12 | `(´；ω；｀)` 被切成两半 | 按句末标点切分，不认括号 | 实测复现 |
| 13 | 一条记忆被永久覆盖，而命中率反而升高 | 「了，」这种标点窗被当成同一件事 | 评测 |
| 14 | 指标虚高、掩盖了排序设计 | 拿整体排序前三当命中，而身份类排在命中之前 | 评测 |
| 15 | 自述一周内被重复写 | 用 `at === 0` 当「没写过」的哨兵 | 测试 |

**教训**：第 13、14 条是同一次评测里发现的，而它们都让分数**变好看**。
所以评测的价值不在分数高，在于它能不能让「分数虚高」露馅。

## 事故与恢复（2026-11-03 → 11-04）

**17:52，`D:\大烧货\工作区` 在一次 DSH 重启中变成空目录。** 只有 `.serena` 活下来。

丢了：源码、22 个提交、`docs/design/` 的附录 A 与附录 B。

为什么查不出原因：DSH 不写应用日志；能确定的只有时间点（目录 mtime 17:52:57、`cordis.yml` 17:52:54），以及「不是更新」——版本仍是 44.7.0，安装文件全部停在 10-29。

怎么救回来的：

| 步骤 | 结果 |
|---|---|
| 解压会话日志（9.7 MB → 26 MB，12983 条记录） | 里面有每一次 `write` / `edit` |
| 按时间顺序重放，`callId` 去重 | 87 个文件 |
| 处理 58 处对不齐的补丁 | 出现重复代码块，手工切掉 `card.js` / `life.js` / `host.js` 三处 |
| 补回 4 个丢失的测试块 | 从日志里原样取回 |
| 逐条修红 | 282 → 286 全绿 |

顺带修出来的两个真 bug（不是恢复造成的）：

- `forgottenAt` 用真值判断，而遗漏时间可以是 `0`，会把「已遗忘」当成「还记得」
