### 2. `retry` 丢图

**现在什么样**：他这一轮发了图，她同时写了 `[查:…]` → 第二次 `complete()` 重建 messages 时
不带 images（`session.retry` 只走 `withStamps(history)`，图原本只贴在 `prompt()` 的最后一条上）。

**症状**：她查完再说一遍时，会假装没看见那张图。

**要做什么**：把这一轮的 `images` 一起带进 `retry`。签名改成 `retry(context, { images })`，
在 `prompt()` 里记住本轮 `shown`，companion 透传。

**验收**：单测——带图的轮次里触发 refine，第二次调用的 messages 末条仍带 images。

**风险**：低。`MAX_TURN_IMAGES` 已经在那限着。

### 3. 多个 `[查:…]` 只执行第一个

**现在什么样**：`searchFor` 取 `searches[0]`，其余静默丢弃——不报错，她自己也不知道没查。

**要做什么**：二选一，别两头空。
- **A（省）**：只取第一个，但把其余的从文本里剔掉（现在已经是剔掉的），并在材料块里写
  「（你这次只查了『X』，别的没查）」，让她知道自己没查全。
- **B（准）**：最多合并成一次查询（`A + B` 拼一起），额度只扣一次。

建议 A：合并查询会把两件事搜成一锅，结果更差。

**验收**：单测——两个 `[查:]` 只产生一次搜索，材料块里含「只查了」。

### 5. 记忆卡带上下文

**现在什么样**：记忆里存的是**她说过的那句话本身**：

```
「这是菲比啾比」
「她叫菲比」
```

注入时是 `- [今天] 她叫菲比`。「她」是谁，记忆里没有。她就得替你补主语，于是像在猜。

（11-14 已经加了协议第 7 条：别补主语，想不起就说想不起。那是**行为层**的补丁，数据层没解决。）

**要做什么**：`remember()` 存 chatter 时把**上一句他的问题**也存进去，例如：

```
{ text: '她叫菲比', askedBy: '金发那个叫什么', at: ... }
```

注入变成 `- [今天] 你问他「金发那个叫什么」，答「她叫菲比」`。

**验收**：`render()` 输出带上下文；2200 字预算下仍然塞得下（每条约多 15 字 → 大约少一条记忆，要实测）。

**风险**：中——记忆的数据结构变了，老记录没有 `askedBy` 要能兼容（没有就退回现在的样子）。

**实施记录（已做）**：`askedBy` 只在 `kind === 'chatter'` 时存（身份/事件类自己站得住，加了就是
「你刚说「我养了只猫」，答：我养了只猫」）；只认 10 分钟内的上一句（隔夜说「刚」是骗人）；
检索索引也带上了它（「金发那个」能翻出「她叫菲比」）。

**实测**：一开始每条都加前缀，2200 字只装得下 36 条，比原来自动少 22 条（每条多 45 字）。
所以改成**只给 ≤12 字的短片段加**——短片段才是丢掉主语的（「她叫菲比」「还行」「明天」），
长句自己带够了信息。改完长句仍是 58 条，短片段 60 条，预算没被吃掉。

### 6. ④ 行为账本 + 周复盘

**现在什么样**：她不知道自己在重复什么。人格卡里写着「不要每条都关心人」，但她**看不见自己犯没犯**。
`looksStuck` 只在当下那一轮提示，不沉淀。

**要做什么**：

1. 每轮结束记一行 `behavior-YYYY-MM.jsonl`（只追加，按月一个文件）：
   ```json
   {"at":...,"parts":2,"chars":18,"situations":["night"],"stuck":true,"refused":false}
   ```
2. 周报生成时（`refreshInsights`）把这一周的统计做成一段材料喂进去：
   连发条数分布、`stuck` 次数、命中情境分布、最常说的一句话
3. 让她自己写那一句「这周你有 12 次在说同一个意思」

**怎么算「refused」**：不加新模型调用。用规则：回复里出现「不行/不」「不想/不要」且整句 ≤12 字，
记为疑似拒绝。**标注为「疑似」**，不当作事实。

**验收**：一周后 `insights.json` 里出现带数字的自述，且数字和账本能对上（测试用假账本验算）。

**风险**：**最高的一项**。周报是「她对自己变化的说法」，喂错统计会污染自我认知。
所以：账本只记行为（条数/字数/情境/是否打转），**不记他说了什么**，也不做任何评价。

**实施记录（已做）**：`src/behavior-log.js` + `behavior-YYYY-MM.jsonl`（跨月读得上、坏行跳过）。
行里多存一个 `open`（她那句话的前 6 个字）——够数「最常用来开头的是「嗯我在」，12 次」，
又不用把整段话存下来。`refused` 只认 ≤12 字的短拒绝，长句里的「不」不算，且一律标「疑似」。
同一句话少于 3 次不报（巧合不是规律）。少于 10 轮不喂给周报。
面板「这周她的说话习惯」能直接看见账本，验收不用等一周。

**已知边界**：`open` 是「开头 6 个字」，不是「整句相同」；她说「嗯……我」和「嗯……你」
会算成同一句。要精确就得存全文，那不划算——打转次数（`stuck`）才是主指标。

### 8. 图片描述：按情绪决定留多少（**你已定：A**）

原来的三个选项（A 留／B 模糊／C 不存）是**按内容类型切**，方向就错了：同样一张图，凌晨吵架时发的和
下午闲着时发的，分量完全不一样，内容类型却一样。改成按**那一刻有多重**来分。

**先确认问题是真的**（已核对代码，不是想象）：`mailbox` 收的是已经被 `withImageText` 加了画面描述的
文本 → `processBatch` 里 `parts: batch.texts` 就是它 → `remember` 逐条入库 → 每轮注入。

**数据已经在手上**，只差一根线：

```
appraise(这一句) → pushEmotion → memoryBlock(msg,{mood}) → remember 存成 rec.feel={v,a}
                                                            ↓
                                              targetClarity()  ← 断在这里，没看 feel
```

`heat`（写入时冻结，之后不重算——和 `feel` 一样，否则你哪天心情差就觉得过去全不重要）：

```js
heat = appraise 认出情绪时 → 这一句自己的 intensity
       认不出（发图就是这样）→ 当前情绪强度 / 2
```

改动四处：

| 位置 | 改什么 |
|---|---|
| `remember` | 存 `rec.heat`；图片那轮正文只留一句 gist，画面描述进 `rec.detail`（`render` 不读 detail） |
| `targetClarity` | `+ Math.round(heat * 30)`（现有幅度：新近 +18、被想起最高 +12） |
| `maintain` | 遗忘闸门加 `heat < 0.35` |
| `render` | 只管 `text`，`detail` 永远不进上下文 |

三档：

| 档 | 判据 | 动作 | 她表现成 |
|---|---|---|---|
| 全留 | `heat ≥ 0.6` | clarity 下限 clear、永不清除、细节留着 | 「那天你说……」能说出前后 |
| 留一部分 | `0.35 ≤ heat < 0.6` | 只留 gist，detail 丢掉，照常老化 | 「你发过一张图，我那会儿挺高兴」 |
| 忘掉 | `heat < 0.35` | 现有规则不动 | 想不起来 |

**A 的含义**：负向高热（`heat ≥ 0.6` 且 `feel.v ≤ 0.4`）→ 留「发生过什么 + 我当时多难受」，原话细节
降档（clarity 封顶 `clear`）。正向高热全留。

**两条已知的坑**（不是待办，是这套东西的边界）：

- 尺子粗：`intensity` 靠词表 + 感叹号，热聊里会累加饱和到 2。所以 heat 只能当**第二根轴**，
  不能替掉 `importance`——内容轴管「值不值得记」，情绪轴管「记多清楚」。
- 老数据 3000 条没有 heat：不重算（重算等于伪造当时的情绪），用 `importance/100` 折算兜底。

**验收**：挑三条（一条感叹号最多的、一条普通闲聊、一张图），一个月后面板里的 clarity 按 heat 排序。
