## 二、逐项

### 1. 重启 DSH

**现在什么样**：运行中的插件是 `c0146f4` 那一版。面板有「他那边」，没有「表情：」——所以
「知道你此刻在干什么」是活的，**表情包、上网查、方括号协议全都没加载**。

**要做什么**：重启一次。第一次启动会拉 13 张收藏并逐张起名（每张一次视觉调用，十几秒）。

**验收**：面板运行那行出现「表情：13 张，13 张有名字」。

---

### 2. `retry` 丢图

**现在什么样**：他这一轮发了图，她同时写了 `[查:…]` → 第二次 `complete()` 重建 messages 时
不带 images（`session.retry` 只走 `withStamps(history)`，图原本只贴在 `prompt()` 的最后一条上）。

**症状**：她查完再说一遍时，会假装没看见那张图。

**要做什么**：把这一轮的 `images` 一起带进 `retry`。签名改成 `retry(context, { images })`，
在 `prompt()` 里记住本轮 `shown`，companion 透传。

**验收**：单测——带图的轮次里触发 refine，第二次调用的 messages 末条仍带 images。

**风险**：低。`MAX_TURN_IMAGES` 已经在那限着。

---

### 3. 多个 `[查:…]` 只执行第一个

**现在什么样**：`searchFor` 取 `searches[0]`，其余静默丢弃——不报错，她自己也不知道没查。

**要做什么**：二选一，别两头空。
- **A（省）**：只取第一个，但把其余的从文本里剔掉（现在已经是剔掉的），并在材料块里写
  「（你这次只查了『X』，别的没查）」，让她知道自己没查全。
- **B（准）**：最多合并成一次查询（`A + B` 拼一起），额度只扣一次。

建议 A：合并查询会把两件事搜成一锅，结果更差。

**验收**：单测——两个 `[查:]` 只产生一次搜索，材料块里含「只查了」。

### 5. 记忆卡带上下文

**现在什么样**：记忆里存的是**她说过的那句话本身**：

```
「这是菲比啾比」
「她叫菲比」
```

注入时是 `- [今天] 她叫菲比`。「她」是谁，记忆里没有。她就得替你补主语，于是像在猜。

（11-14 已经加了协议第 7 条：别补主语，想不起就说想不起。那是**行为层**的补丁，数据层没解决。）

**要做什么**：`remember()` 存 chatter 时把**上一句他的问题**也存进去，例如：

```
{ text: '她叫菲比', askedBy: '金发那个叫什么', at: ... }
```

注入变成 `- [今天] 你问他「金发那个叫什么」，答「她叫菲比」`。

**验收**：`render()` 输出带上下文；2200 字预算下仍然塞得下（每条约多 15 字 → 大约少一条记忆，要实测）。

**风险**：中——记忆的数据结构变了，老记录没有 `askedBy` 要能兼容（没有就退回现在的样子）。

### 6. ④ 行为账本 + 周复盘

**现在什么样**：她不知道自己在重复什么。人格卡里写着「不要每条都关心人」，但她**看不见自己犯没犯**。
`looksStuck` 只在当下那一轮提示，不沉淀。

**要做什么**：

1. 每轮结束记一行 `behavior-YYYY-MM.jsonl`（只追加，按月一个文件）：
   ```json
   {"at":...,"parts":2,"chars":18,"situations":["night"],"stuck":true,"refused":false}
   ```
2. 周报生成时（`refreshInsights`）把这一周的统计做成一段材料喂进去：
   连发条数分布、`stuck` 次数、命中情境分布、最常说的一句话
3. 让她自己写那一句「这周你有 12 次在说同一个意思」

**怎么算「refused」**：不加新模型调用。用规则：回复里出现「不行/不」「不想/不要」且整句 ≤12 字，
记为疑似拒绝。**标注为「疑似」**，不当作事实。

**验收**：一周后 `insights.json` 里出现带数字的自述，且数字和账本能对上（测试用假账本验算）。

**风险**：**最高的一项**。周报是「她对自己变化的说法」，喂错统计会污染自我认知。
所以：账本只记行为（条数/字数/情境/是否打转），**不记他说了什么**，也不做任何评价。

### 7. QQ 空间端到端

**现在什么样**：`qzone.json` 里 `lastTid` 是空的，`get_qzone_msg_list` 的解析是坏的，
发表 → 读评论 → 回评论 → 删这条链**从来没有一次完整跑通过**。

**要做什么**：先用面板的 `?qztest=1` 强制发一条，再走一遍评论/删除。
哪一环断就修哪一环（已知 `get_qzone_msg_list` 解析坏，`comment_list`/`like_list` 返回 1404）。

**验收**：发一条 → 你自己去 QQ 空间留个评论 → 她读到并回复 → 面板删除，四步都通。

**风险**：中——外部接口，可能根本没有能用的读评论接口，那就只能退回「只发不读」。

### 8. 记忆里那些图片描述怎么办（**要你决定**）

**现在什么样**：她记着他发过的图的详细描述，其中有些是成人内容的画面描述。这些描述会跟着记忆卡
一起被注入每一轮的上下文。

**这不是 bug，是策略缺口。** 三个选项：

| 选项 | 效果 | 代价 |
|---|---|---|
| A 留着 | 她记得完整 | 上下文里长期有这些内容，模型可能主动提起 |
| B 模糊化 | 存成「你发过一张图」 | 丢掉细节，也丢掉「她记得」这件事 |
| C 不存 | 图片描述不进记忆卡 | 最干净，但她对发过的图完全失忆 |

我倾向 **B**：保留「你发过图、我当时什么反应」，去掉画面细节。她记得的是**那件事**，不是那张图。

**这条不改代码，改的是写入记忆时的规则。**

## 三、建议顺序

```
1 重启（1 分钟，解锁全部已完成的）
   ↓
2 retry 丢图（小，且会让「查」在带图的轮次里出错）
3 多个 [查] 合并（小，同一处代码）
   ↓
4 面板表情图库（能看见才能调，改名会立刻改善她的挑图）
5 记忆卡带上下文（数据结构变更，单独一批）
   ↓
6 ④ 行为账本（观察一周）
   ↓
7 QQ 空间端到端（外部接口，可能卡住）
8 图片描述策略（等你决定，随时可插）
```

理由：2 和 3 在同一段代码里，一起改一次；4 和 5 都要动数据，分开做；
6 必须在 ①②③ 稳定之后（否则账本记的是不稳定版本的噪声）。

## 四、这份表不做什么

- 不为了凑数把小问题写成任务；`night` 情境太宽那种，是「观察两天再说」，不是待办。
