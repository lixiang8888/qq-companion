## 一、这轮做了什么

### 1. 先做了一次全仓审计（`ponytail-audit`）

查出 8 个问题，全部修完并各有测试（提交 `7a4f8fa`）。影响最大的两个：

- `host.js` 里 `memoryBlock: (msg) => memoryBlock(msg)` 把第二个参数丢了 → 情绪重量 `heat` 恒为 0、`feel` 从未写入（真实数据 255 条记忆、0 条有 feel）。

其余：陌生人私聊越过身份检查（会花视觉调用钱、污染 `recallLines`）；`[查:]` 重答时草稿进了归档；多图只说了两张；`noteWait` 忽略配置的安静时段；`stickerSends` 只增不减。

## 二、最终行为（第二轮改造后）

| 场景 | 行为 |
|---|---|
| 图在 **24 小时内**，或在**最近 30 轮对话**里 | 每轮直接带**完整描述**（≤80 字），不需触发词 |
| 更早的图，语义命中（分 ≥0.15） | 提一句「你看到过的：…」 |
| 分 **≥0.4** 且这轮没发图 | **把原图缩到 512px 贴回她的回复调用**，她当场重看 |
| 这轮他发了图 | 两个块都跳过 |
| 候选 ≥2 | 先给模型看缩略图选一张，回「都不是」就不提（≤5 次/小时） |
| 只有描述的老图（迁移来的） | 能搜到、只提文字，跳过复核 |

清理由两条规则：2GB 上限（删最老原图、留记录和缩略图）；冷清理（**有文件可回收** + `hits=0` + 超 90 天 + `heat<0.35` → 整条删）。

## 三、过程中做过的裁量（免得以后反复问）

- 触发**不看关键词**：旧的 `shouldRecall`/`RECALL_TRIGGER` 已删（用户明确说"不能靠『图』字"）。
- 召回门槛 **0.15**（实测真命中 0.22、无关 0；`search()` 会乘重要度 0.75 和清晰度 0.5）。重看门槛 0.4。
- 感知记录写 `importance:100 / clarity:'vivid'`，不吃记忆卡的缺省折扣（否则两张像的图就把分数压到门槛下）。
- `candidates()` 返回 `{rec, score}`（重看要不要贴图按分数决定）。
- 注入块 `at` 用**此刻**（用记录时间会让 ttl 5 分钟的块一出生就过期）。
- 冷清理只处理"有文件可回收"的记录（否则迁移来的、只剩描述的那 26 条会被一次心跳删光）。
- 移动端 26 条老记录：迁移时 `heat: null`（**不伪造当时的情绪**），靠上面那条保护。

## 四、还没做的

1. **`--write` 没跑**。dry-run 显示 26 条待迁移（17 整段 + 9 另一种旧格式 + 4 占位跳过）。跑完收益：省 2341 字上下文 + 老图能文字搜到。回滚：`memory.json.bak-migrate`。
2. **真机没验**。只有假 fetch 的测试。三个没验证的假设：模型能否稳定回三字段 JSON、复核能否挑对、QQ 图链换链成功率。
3. **没有「忘掉这张图」的入口**（面板只有记忆卡的忘记）。
4. **孤儿文件**：`perception.json` 读坏被重置后，盘上的图没人引用也不会被清。
5. **单张图不限大小**：20MB GIF 原样落盘，靠 2GB 总量兜。

## 五、怎么验（真机）

1. 发一张图 → `perception.json` 出现 1 条、`perception/2026-11/` 下有原图和缩略图。
2. 接着聊别的（**别说「图」**）→ 24 小时内它该自动带着描述。
3. 说「你上次那个粉头发的」→ 她该把图重看一遍（那一轮会描述画面细节，不只是复述标题）。
4. 面板看 `图 N 张（原图 M 张，占 X MB）`。
