## 一、这是什么

她无聊的时候会自己去读小说：接上次那本往下读一章，读完写两三句自己的反应。正文读完就丢，只留一句感想和进度。

**为什么绕这么远**：网文站基本 JS 渲染/反爬，我实测过「直接抓页面 + 启发式提取正文」，24 个精选源 **0 个能读**（顶点小说：搜索通、352 章目录通、正文只有 28 字）。所以让 Legado 去跑那 176 条书源规则，插件只跟它的 Web 服务说话。

**用到了哪个开源 APK**：[Legado /「阅读 3.0」](https://github.com/gedoor/legado)（原 GPL-3.0，Kotlin，约 47.2k★）。**只装在模拟器里当外部程序用，仓库里不含它的代码或 APK**，记录见 [THIRD_PARTY_NOTICES.md](../../../THIRD_PARTY_NOTICES.md) 与 [docs/references.md](../../references.md)。
⚠️ 2026-11-18 核对：**上游仓库已被作者清空**（2026-05-27），公告承认侵权并删除全部内容；公开报道称两位开发者以侵犯著作权罪被判刑。技术照旧可用，但「自用」不等于没风险——详见上面两个链接。

```
插件(novel.js) --HTTP--> Legado(Android, 176 条书源) --> 网文站
                        ↑ 跑在 apkstart 的运行时里
```

## 二、现在跑成什么样

**后端**：apkstart 的 emulator + Android 14 Play 镜像，手工建的 AVD 叫 `qqreader`，headless。

| 项 | 值 |
|---|---|
| AVD | `%USERPROFILE%\.android\avd\qqreader.avd`（Legado + 书源 + 书架都在 userdata 里，重启不丢） |
| adb 端口 | **5038**（避开 MuMu 的 5037） |
| 模拟器端口 | 5580，serial `emulator-5580` |
| 端口转发 | `adb -P 5038 -s emulator-5580 forward tcp:1123 tcp:1122` |
| PC 侧入口 | `http://127.0.0.1:1123` |

**三个接口**（真机实测，参数名叫 `url` 但传的是**书的地址**，不是章节地址）：

```
GET /getBookshelf
GET /getChapterList?url=<bookUrl>
GET /getBookContent?url=<bookUrl>&index=N
```

`/searchBook` 走 GET 是坏的（返回 500，body 就是 `web/searchBook`），**不要依赖它**。书由人在 App 里加。

**默认源 = 顶点小说**（他的决定：质量高）。例外 4 本，原因都是顶点那本更差（不分段 / 缺章 / 防盗替换字）。
**换源不是「换完就行」，每本都要抽样核正文**：章数一样不代表文字对——防盗替换字只能靠换源解决，洗不掉。

换源怎么做的（批量可复用）：书架长按书 → Book information → **Change Origin** → 放大镜（按源名过滤）→ 输入源名（「玄幻阁」/「顶点」）→ 点结果行。
坑：源名在**搜索框里也有一份**，按文本匹配时要排除 `EditText`，否则点的是输入框。用「包含」匹配而不是「等于」，源名带后缀也能命中。
脚本：`D:\大烧货\工作区\.tmp\switch-all-dd.ps1`（批量换 + 掉章自动回滚）、`switch-dd.ps1`（单本）。
**按源搜索的 HTTP 接口是坏的**（`GET/POST /searchBook` 都 500）：真正的搜索是 WebSocket `ws://host/searchBook`，要 `legado.token.<base64url(令牌)>` 子协议，令牌是 App 里「Web 与 MCP 访问令牌」，现在没配——所以别指望用搜索做「查别的源」，只能靠书架里的书。

教训：**「0 章」不能直接判成坏源**，先刷新一次目录——那是一条网络失败，不是源坏了。

换源后实测的两个新毛病（写进 P1 一起修）：

1. **玄幻阁也会塞混淆广告**：遮天第 1 章开头有 `\\wＷｗ。 q Β5 .COM \．` 这种夹在正文里的站点广告，`cleanText` 的规则认不出。只看第 1 章会有，第 3/6 章干净。
2. **占位章节会让读书卡死**：宿命之环第 1 章只有 127 字（「作者大大正努力存稿中…请重新刷新页面」）。`readNovelIfBored` 遇到 `<200` 字是 `return st`（不推进进度），下一轮又选中同一章——**会永远重试**。要改成「跳过并前进」。

## 四、这一轮拍板的事

- **80 章是上限，不是目标**（他明确说的）。触发条件仍然是「他安静 ≥2 小时」，所以常说话的日子她一章也不读——这是对的。
- 两章之间隔一次心跳（10 分钟），不在一个 tick 里连读。
- **按章号走，不按下标走**。真实毛病：有的源同一章列两次，有的缺章。按章号只在「章号变大」时读 → 重复的永远选不中；跳号就把缺了几章写进 log。
- 感想：两三句、≤80 字。先写此刻什么滋味，再说一句对人或事的看法，可以带一个细节。不要复述剧情、不要评价文笔、不要写旁白。
- 读书**不排队列**（拉正文 + 模型调用十几秒，会堵住他刚发的消息），函数内部有 `reading` 并发闸。
- 一章 <200 字判定这条源坏了，这次跳过，不换章硬凑。
- 正文不进历史、不进记忆卡。

**真章跑过的样例**（斗破苍穹第一章，两个提示词对比）：

- 原来（≤30 字）：`有点堵得慌，薰儿这种时候还站他旁边。`
- 现在（≤80 字）：`有点闷。那群人翻脸比翻书还快，三年前还点头哈腰呢。指甲掐进掌心那段看得我手心也跟着疼，这小子倒是没哭。`

## 五、运维：一个桌面脚本

`C:\Users\19472\Desktop\启动全部.bat` → 调 `D:\大烧货\apkstart\启动阅读器.ps1`（7 步：DSH → SnowLuma → adb → 模拟器 → 拉起 Legado → 点开 Web 服务 → 体检）。都开着时会全部跳过，只体检。

**四个坑**（前三个都实测踩过，别"优化"掉）：

1. `.ps1` 必须带 **UTF-8 BOM**，否则 `powershell.exe`（5.1）按 ANSI 读，中文变乱码直接语法报错。注意：某些编辑器/补丁工具会**把 BOM 删掉**，改完要查前三字节是不是 `EF BB BF`。
2. 从 DSH 进程里拉 Electron 程序前要 `Remove-Item Env:ELECTRON_RUN_AS_NODE`，不然 exe 退化成纯 node、什么都不做直接退 0（apkstart 之前「点了没反应」就是这个）。
3. `.bat` 必须**全 ASCII**，两个原因叠加：cmd 按系统代码页（936）读 .bat，存 UTF-8 会被拆行（`title 启动 SnowLuma` 变成去执行 `nowLuma`）；而且 cmd 把**中文参数**传给子进程会坏（实测 `-File "D:\<中文目录>\x.ps1"` → `does not exist`，目录名中文就坏，跟文件名无关）。所以 .bat 里用通配符 `D:\*\apkstart\*.ps1` 定位脚本，绝不写中文路径。
4. 模拟器**正常关机**再开会自己恢复 App 和 Web 服务（快照），但 App 一旦被 force-stop / 重装，**「Web service」开关就回到关闭状态，1122 没人听**。脚本第 6 步用 uiautomator 摸到「我的 → 下滑 → Web service」右边那个开关点开（靠 resource-id `switchWidget` 找，不写死坐标；320x480 屏）；摸不到就打印提示让人手动点。第一次开时 Legado 会弹「允许后台运行」，要手动 Allow 一次（只一次）。
