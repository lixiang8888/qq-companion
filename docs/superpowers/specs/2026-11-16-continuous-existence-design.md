# 连续存在（continuous existence）设计

日期：2026-11-16 · 状态：待你确认 · 项目：qq-companion

## 一、要解决的是什么

> 「目前的一切交流，归根到底就是你一句我一句的方式。」

这不是错觉，是结构。三条，都能指到行：

**1. 她的世界只在他开口那一刻采样一次。**

`contextBlock(msg)` 整条链挂在回复路径上（`host.js:708`）：天气「过期就当场问一次：**她开口时**天气应该是当下的」（`host.js:711`）、屏幕「五分钟外的自己过期」→ 现读（`host.js:724`）、图片现召回（`host.js:729`）。

他沉默十小时，这十小时里她的世界是**冻结的**。没有新天气、没有新屏幕、没有"这几天一直挂着的事"。所以他一旦不说话，她就无事可做、无话可说——她唯一能说的是"他刚说的那句"。**这就是"一句来一句去"的根。**

**2. 一轮是原子的：整段生成完，才发第一条气泡。**

`llm.js:47` 把流式 chunk 全吞进 `out` 再返回；`session.js:222` await 完整结果；`host.js:1284` 才 `splitReply` 逐条发。第一条气泡的延迟 = 整段生成的延迟。

**3. 她只有两种模式。**

- 答他：`processBatch`
- 决定要不要找他：`tickProactive`（`host.js:1519`，`proactive.js:18` 的默认：一天 3 条、要闲 180 分钟、连发 2 条就停）

没有第三种。她没有"想一想"、"干点什么"、"什么都不做"。

## 二、目标 / 非目标

**目标**

1. 她的世界在**他不说话的时候也变化**——而且只由**真事**驱动（不掷骰子）。
2. 第一条气泡的延迟从"整段生成"降到"一句话"。
3. **不增加**模型调用次数（理想是持平或更少）。
4. 现有的每一道闸（安静时段、每日上限、心情地板）继续有效。

**非目标**

- 不做语音、不做全双工（`kyutai-labs/moshi` 那条路要 GPU + 语音，和他现在的 QQ 文字不是同一个产品）。
- 不引入任何新依赖、不搬家、不换成 agent 框架。
- 不做"打断她正在生成的那句话"（见 §七）。
- 不做多智能体。

**反面目标（做到这些算失败）**

- 她话变多了，但说的都是"我想你了"这种没来处的句子。
- 每日 token 翻倍。
- 同一句话说两遍。

## 三、约束（查过代码和真实账本）

- **真实用量**（`budget.json`，2026-11-15）：21 次调用 / 输入 37487 / 输出 4368 / 缓存 23552。
  **摊到每次：约 1785 输入 + 208 输出。** 这是本设计算成本的唯一依据。
- 同一天记下的余额是 **1.96 元**（账户余额，DSH 也用同一个账户，不全是她花的）。
  所以"多几次调用"不是学术问题。
- 今天已经在调的模型调用来源：对话轮次、`refreshLife`（`host.js:1510`，`life.until` 到了才问，计划 5–180 分钟）、`tickProactive`（≤12 次/天）、`refreshInsights`（每周）、`refreshDiary`、压缩、`[查:]`。
- `sentenceUnits`（`message.js:105`）已经会按句末标点切句、**且括号没闭合不切**（颜文字不被切两半）——这正是流式发句需要的那个原语。它现在**没有 export**。
- `parseActions`（`actions.js:12`）的 MARK 正则要求 `[表情:…]` / `[查:…]` 闭合。
- `pokeGate`（`proactive.js:138`）已经是一套完整的闸，可以直接复用，不用重写。
- `life.js` 的 `applyPlan` 已经是"她说自己在干什么 → 记住 → 到点清空"的状态机。
- `tickProactiveInner`（`host.js:896`）**已经就是这个 tick 的雏形**：过闸 → 拼提示（时钟、闲了多久、最后一句、挂着的记忆、上次想过什么、此刻在干什么）→ 一次调用 → 解析 JSON → 存 `lastThought` → 发。B 的主要工作是**改输入、加两个输出**，不是重写。
- `lastThought` 已经在存"她上次想的是什么"，而且已经在被读回（`host.js:937` 写、`host.js:918` 作为 `inner` 读回）。**`think` 不需要新文件。**
- `createJsonStore.load()` **每次都真读文件**，没有读缓存（`store.js:10` 的 5 分钟是 **.bak 备份节流**，不是读缓存）。`save()` 是"临时文件 + rename"，原子;但**并发读-改-写会互相覆盖**（后写的赢）。

## 四、做了哪些取舍

| 想法 | 为什么不 |
|---|---|
| 换成 LangGraph / AutoGen / CrewAI 这类编排框架 | 它们编排的是"几个 agent 谁先说话"，不解决"她有没有自己的时间"。换过去等于重写，还更不像人 |
| 装 `ai-town` / `generative_agents` | 研究代码 + 自带一个虚拟小镇世界，和 QQ 私聊没有交集。要偷的是**循环的形状**，不是代码 |
| 接 `airi` / `N.E.K.O` | 都是完整产品（语音 + Live2D + 插件市场）。但 N.E.K.O 的 README 证明了一件事：**她沉默时想什么可以全用真素材**（屏幕、B站热榜、贴吧、音乐），不用编 |
| 拆队列 + 打断她（原计划的第三件事） | **砍掉**，理由见 §七 |
| 每分钟一次 tick，不管有没有事都问模型 | 账户只剩一块多，而且"没事也想"必然产出没来处的句子——正好是他最讨厌的那种 |

## 五、改动 A：流式发句（半天）

**目标**：第一句生成完就发出去，不等整段。

### 怎么改

1. `llm.js` 的 `complete()` 加可选 `onDelta(text)`，在 `text-delta` 到来时回调；**返回值不变**（仍然返回累积的整段），所以现有全部调用方零改动。
2. `session.prompt` 加可选 `onSentence(fn)`：内部维护缓冲，每凑出一个"完整句子"就回调一次。切句复用 `sentenceUnits` 的规则（要 `export` 它，或在 `message.js` 里加一个 `pushSentence` 小函数——**选后者**，`sentenceUnits` 保持私有）。
   - "完整句子"= 遇到 `。！？!?…；;` 且括号深度为 0，且这一句 ≥2 字。
   - 若当前句里出现**未闭合的 `[`**，不切（标记会跨标点）。
3. `processBatch` 用上它：第一句到时立刻 `sendText` 并 `await sleep(plan.delayMs)` 再发下一句；`plan.maxParts` 仍是条数上限（超了就停发，剩下的丢弃——和今天 `splitReply` 的 `slice(0,max)` 一致）。
4. 收尾：`sentText` = 已发出的句子按原样拼接。`appendTranscript`、行为账本、`session` 历史**都用 `sentText`**，不用模型吐出的整段（否则历史里会有他从没看见过的话）。
5. 降级：`onSentence` 一次都没被调过（模型一次吐完、或出错）→ 走今天的老路径 `splitReply`，行为完全不变。

### `[查:]` 的规矩（这是要你点头的一条）

`[查:]` 今天会触发 `retry`，**整段回复被第二版取代**（`session.js:254`）。流式一发出去就收不回来。所以：

> **`[查:]` 只在"还没发出任何气泡"时有效。** 已经发出去第一句之后再出现 `[查:]`，按普通文本处理（`[` `]` 括起来的内容照旧从正文里剔掉），**不重答**。

配套：提示词里加一句「要查东西，就把 `[查:…]` 写在最前面」。今天她本来就是这么写的（要材料才能答，自然会先写）。

代价：极少数情况她"想查但没说"。收益：绝不会出现同一句话被说两遍、或发出去了又撤回——那两种比少查一次糟得多。

### `[表情:]`

随句解析、随句剔掉，贴图仍在全部文字发完之后发（`host.js:1291`，不变）。

## 六、改动 B：能自己推进的 tick（2–3 天，这是主要的一件事）

### 形状

把"一次模型调用"改成 **`感知 → 决策 → 行动`**，而且**感知是免费的**。

```
每 10 分钟（现有 heartbeat）
  └ perceive()  ← 纯函数，只读本机状态，不调模型
       └ events 为空  →  到此为止（她的世界没变化，她就不需要想）
       └ events 非空  →  一次模型调用（合并掉今天的 refreshLife + tickProactive）
            └ { say, doing, think }
                 say   → 过 pokeGate 的闸 → 发
                 doing → 写 life（取代 refreshLife 那次调用）
                 think → 追加到私有日记，只作为下次 tick 的输入
```

### `perceive()`：事件必须是真的

只收这些来源，每一条都能指到文件／字段：

| 事件 | 判定 | 素材来源 |
|---|---|---|
| `screen` | 屏幕开着，且窗口标题和上次不同 | `screen.json` |
| `weather` | 天气超过 12 小时没更新，且现在是早上 6–10 点 | `weather.json` |
| `silence` | 他超过 6 小时没说话 | `session.json` 最后一条 user 的 `at` |
| `unfinished` | 有没说完的话题 | `pendingQuestions` |
| `memory` | 今天新增了记忆卡 | `memory.json` 的 `at` 落在今天 |
| `diary` | 今天还没写日记 | `diary-snapshot.json` |
| `money` | 余额低于 `budget.lowBalance` | `budget.json` |
| `doing` | `life.until` 到了 | `life.json` |
| `picture` | 最近 24 小时他发过图 | `perception.json` |

**没有事件就不调模型。** 这条是整个设计的核心：她的"想法"必须有来处，来处是真实的文件。这也顺便把成本压住了。

### 模型那一次调用

输入（都很小）：

```
【你现在的样子】  insights 的周自述（≤200 字）+ 此刻（clockLine）
【上次你想的】    lastThought（≤60 字）
【外面发生了什么】events（每条一行，≤40 字）
【你们最后一句】  最后一条对话（≤120 字）
```

输出只回一个 JSON。**在现有形状上只加两个键**，`send`/`message`/`waitMinutes`/`reason`/`search` 全部不动，
这样 `parsePokeReply`（`proactive.js:201`）和它的测试一行都不用改：

```json
{"send":false,"waitMinutes":45,"reason":"…","doing":"","think":""}
```

- `send`/`message` → 一个字节都不改。`say` 空（`send:false`）是**默认**，提示词里要明确"什么都不做也完全没问题"。
- `doing` 空 → 不动 `life`；非空 → 走现有 `parsePlan`/`applyPlan`（`life.js:30`），分钟数缺省 60。
- `think` → 写进 `lastThought`（`proactive.json` 的**已有字段**，`host.js:937` 已经在写、`host.js:918` 已经在读回）。
  所以**不新增文件**，只把存的内容从"整段原始回复"改成解析出来的 `think` 那一句——
  今天 `lastThought.text` 里存的是 `{"send":true,"message":"喂"}` 这种原文，回灌给她是噪音。
  **`think` 不进对话正文、不进记忆卡**——它是她自己的一条线，只在下一次 tick 里被读回来。
- `waitMinutes` → 沿用 `noteWait`（`proactive.js:125`），把下一次机会往后推。

### 和 `tickProactive` 的关系

**合并成一个决策者，不并列。**

今天的 `tickProactive`（`proactive.js:138` 起）已经有全套闸：安静时段、心情地板、每日上限、最小间隔、连发上限、每日思考上限、期待时间。这些**一条都不改**，只做三件事：

1. 它的输入从"要不要找他"扩展成上面的 events；
2. 它的输出加两个键 `doing` / `think`（`send`/`message` 不变）；
3. `refreshLife` 的模型调用**删除**，`doing` 由这次调用一起产出。

结果是：**调用次数持平或更少**（原来 `refreshLife` 和 `tickProactive` 各调各的），而她的世界开始自己动。

### 成本（用真实账本算）

- 一次 tick 调用 ≈ 800 输入 + 120 输出，约为一次聊天调用（1785/208）的**一半**。
- 按 16 小时醒着 = 96 次机会，事件非空的经验比例假设 20%~30% → **20~30 次/天**。
- 今天 `refreshLife`（计划 5–180 分钟，实际约 10~20 次/天）+ `tickProactive`（≤12 次/天）= **20~32 次/天**。
- 所以：**持平，合并后略降。** 不新增一个数量级的东西。

真正的成本变量只有一个：**"事件非空"的比例**。这个不能猜，要跑一周看真实数字（`perceive()` 把每次的事件条数记进 `proactive.json`，面板上加一行「这周想了 N 次，其中 M 次是因为外面真有事」）。

## 七、改动 C：拆队列 + 打断 —— **不做**

原计划有第三条：把消息通道从串行队列里拆出来，并允许他中途发消息打断她正在生成的那句。**砍掉**，三个理由：

1. **阻塞是有界的。** 家务每个是一次网络调用（1–5 秒），最坏情况他的消息等几秒；而家务每 10 分钟才跑一次，撞上的概率很低。
2. **收益小于风险。** 拆成两条并发通道之后，两条通道会同时 `save` 同一批 JSON（`budget.json`、`memory.json`、`session.json`）。`createJsonStore` 的写是"临时文件 + rename"，本身安全，但**并发读-改-写会互相覆盖**（丢记忆、丢记账）。为了省几秒，换一个数据损坏的口子，不值。
3. **打断在 QQ 上体验未必好。** 他发的新消息，`mailbox` 的 3 秒合并窗口（`mailbox.js:9`）本来就会把它和上一条合成一轮；她已经说完再答，不会显得慢。

所以：**队列不动。**

## 八、顺序

1. **A 流式发句**（半天，独立，不动数据结构，风险只在 `[查:]` 那一条语义）→ 体感立刻变。
2. **B tick**（2–3 天，这是主菜）→ 她开始有自己的时间。

先做 A，因为它能立刻验证"延迟到底是不是他感受到的那个病"。如果 A 做完他觉得"还是一句来一句去"，那 B 就是唯一的答案；如果 A 就解决了，B 可以慢慢来。

## 九、测试（不联网）

**A**

1. 假 `complete` 分三次吐「好呀。」「那你去吧。」「我等你。」→ 断言 `sendText` 在第二句到达**之前**就被调用过（即不是整段生成完才发）。
2. 括号保护：`（笑。` 未闭合时不在 `。` 处切。
3. `[查:` 出现在第一句**之前** → 一条都不发，走 retry，第二版整段发。
4. `[查:` 出现在第一句**之后** → 已发的照旧，第二版**不**发，`onSentence` 不再回调。
5. `[表情:无语]` 夹在句中 → 不切在标记里，标记从发出文本里剔掉。
6. `onSentence` 从未被调（模型一次吐完）→ 走 `splitReply` 老路径，输出与今天逐字一致。
7. `maxParts` 仍然是上限：心情低时只发 1 条。

**B**

8. `perceive()` 纯函数：给他造九种状态并逐个验证事件出现/不出现；**全都正常时返回空数组**。
9. `perceive()` 返回空 → 一次模型调用都不发生（用计数桩断言）。
10. 事件非空 → 一次调用；`send` 走 `pokeGate`：安静时段/心情低/超每日上限时**不发**，但 `doing`/`think` 照写。
11. `think` 写进 `lastThought`，且**不出现在**下一轮对话的 `context` 里（只出现在下一次 tick 的输入里）。
12. `doing` 缺省 60 分钟；非法值不动 `life`。
13. `refreshLife` 的独立调用被删除后，`life.json` 仍会被更新（回归）。
14. `waitMinutes` 生效：`noteWait` 之后 `pokeGate` 在期待时间之前不放行。

## 十、我拍的小决定（不同意就说）

- 切句阈值 2 字：`嗯。` 这种也算一句——她本来就这么说话。
- `think` 用已有的 `lastThought`，**不新增文件**。一条就够"上次你想的"，等一周发现不够再加历史。
- `perceive()` 的事件最多取 6 条（按上面的表顺序），多余的不带——context 里堆九条她会答非所问。
- 事件表先就这九种，跑一周看够不够。**不要一开始设计二十种。**
- `send:false` 是默认。提示词里必须写死「什么都不做也完全没问题」，否则模型会为了"有产出"硬编一句。

## 十一、风险

- **`[查:]` 语义变了**（§五）：她在第一句之后才想查时查不了。缓解：提示词要求写在最前面。**这条要你明确点头。**
- **事件噪音**：`screen` 的窗口标题变一次就是一条事件，他切浏览器她可能就想说话。缓解：`send` 的闸不动（一天 3 条），事件再多也只是"想过"，不会多说话；但**想也是花钱的**，所以要盯一周的"事件非空比例"。
- **`think` 变成假账**：模型会写"我在想你"这种没来处的话。缓解：只喂真事件、`think` 不回进对话；如果一周后发现全是空话，就砍掉这个输出，只留 `send`/`doing`。
- **读同一个 JSON 的频率变高**：`perceive()` 每 10 分钟读九个文件，而 `createJsonStore.load()` 每次都真读盘（没有读缓存）。
  这些文件合起来约 160 KB（`memory.json` 124 KB 最大），每 10 分钟读一遍可以忽略；
  但如果出现读放大，就复用 `contextBlock` 已经读过的快照，别再加缓存层。
- **B 做完她可能更黏人**：事件里 `silence` 最容易被触发。缓解：它只在"超过 6 小时"时出现，且仍要过 `pokeGate` 的 180 分钟空闲 + 每日 3 条。
