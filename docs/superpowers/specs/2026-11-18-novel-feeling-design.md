# 读书的感受（reading feelings）设计

日期：2026-11-18 · 状态：待批准 · 项目：qq-companion

## 一、要解决的是什么

> 「阅读到小说的爽点，会不会感觉爽；动人的地方是否会有感触；节奏糟糕、强行煽情，读多了之后是否会感到反感。」

三个问题的答案是同一个：**现在都不会**。不是写得不够感人，是结构上不可能。

`readNovelIfBored()`（`host.js:809`–`859`）现在只做两件事：

1. 拉一章正文，喂给模型写 ≤80 字感想；
2. 把感想存进 `novel.json`，注入成一条 12 小时过期的「你 X 小时前自己在看…」（`host.js:759`）。

它**没有调过 `pushEmotion`**——而那是情绪引擎唯一的入口（`affect/core.js:155`，目前只有 `companion.js:40` 在用）。
所以读书这件事：不改变情绪、不改变心境、不改变她下一句话、不进记忆、没有跨章累积、也没有「我不想读这本了」的出口。

**根因一句话：她现在是在评论一本书，不是在经历一章。** 评论不需要改变谁；经历会。

「能感受」最少要满足五条，现在全断：

| 条件 | 现在的状态 |
|---|---|
| ① 感觉是一个存下来的状态 | ✗ 读书不碰情绪状态 |
| ② 由具体的一段文字引起 | ✗ 无结构、无锚点 |
| ③ 它约束了她下一句话/读不读/读哪本 | ✗ 读了等于没读 |
| ④ 按分量留存与衰减 | ✗ 一句话 12 小时，没别的 |
| ⑤ 她自己能归因「我烦是因为那本书」 | ✗ 没有任何跨章累积 |

## 二、目标 / 非目标

**目标**

1. 读书进**同一个**情绪系统：真实反应 → `pushEmotion`；强度 ≥0.3 会带动心境 8 小时，**他下一句话能感觉到**。
2. **情境化**：同一章在她心情好和被他晾了三小时后，读出两个味道。读之前要带她此刻的状态、前两轮聊天的尾巴、以及**她对这本书最近几章的反应**。
3. **对书的态度会累积**，并且有行为后果：弃书 / 追更 / 重读。反感不是形容词，是会发生的事。
4. **强的感触进记忆**（带热度、带当时的心情），几天后能在聊天里自己浮上来。
5. 每天最多一次的**「想一想」**：从最近的反应里长出自己的念头/判断，落盘并注回。「思想」在这一层。
6. 全部由真事驱动：真正文、真反应、真累积。不掷骰子、不编事件。

**非目标**

- 不做「AI 写书评」：不评文笔、不复述剧情（现有 prompt 已经这么要求，保留）。
- 不改后端、不换 Legado、不加新依赖。
- 不动 80 章/天（那是闸，不是目标）。
- 不做「读书涨亲密/信任」——不能拿书当亲近的借口。
- 不做多本并行读：一次一本，跟人一样。

**反面目标（做到这些算失败）**

- 每章都「好感动」「好爽」——说明闸门失效，数值会变成装饰。
- 情绪数值每章乱跳，心境被钉死。
- 她开始为了让他心疼而说「我看哭了」。
- 感想变成同一个句式反复出现。

## 三、约束（查过代码）

- 情绪只有 `pushEmotion`（`affect/core.js:155`）一个入口；`mood` 在情绪强度 ≥0.3 时跟随，半衰期 8 小时（`core.js:106`–`111`）。
- 注入只许影响**语用层**（句长、语气词、接梗、自我披露），不许说出口、不许解释（`affect/inject.js:1`–`7`、`:82`）。
- 记忆卡 `remember()` 支持 `source`（有 `said` / `seen` / `inferred` 三种根）、`heat`、`mood`（`memory/card.js:254`）。
- 读书已经**不在串行队列**里（`host.js:800`–`802`），有 `reading` 闸；新增的「想一想」沿用同样的做法。
- `isBored()` 已有四道闸：`hasBook`、`mood ≥ 0.4`、`readsToday < 80`、`gap ≥ 10min`、`安静 ≥ 2h`（`novel.js:132`）。
- 正文每次最多 `READ_MAX_CHARS = 3000` 字（`novel.js:123`）。
- 真实用量（`budget.json`，2026-11-15）：21 次调用 / 1785 输入 + 208 输出 每次。本设计**每章只多一次已有的调用**，增量是几十个字。
- 书源（2026-11-18 复核）：10 本**都有章节**；只有神秘复苏 44 章（这书本该上千章）要换源。**之前报的「0 章」是取目录失败，不是坏源**——App 打开刷新一次就好了。所以 `nextRead` 遇到 `total === 0` 要「跳过这次、下次重试」，**不能当成弃书理由**。另外目录读完会从头再读（`planRead` 第三条，`novel.js:67`），这条要改。

## 四、模型：三层时间尺度

```
          一章正文
             │
      ┌──────┴───────┐
      │  她的反应     │  一次模型调用，带锚点+标签（§五）
      └──┬────────┬──┘
         │        │
   情绪(分钟)   对书的态度(天)          强反应
   pushEmotion   EWMA 累计              │
         │        │                    ▼
   心境(8h)   弃书/追更/重读      记忆卡(带热度)
         │        │                    │
  下一句话的语气  下次读哪本      几天后自己浮出来
         │
     每天一次的「想一想」→ 念头(周月) → 注回
```

| 层 | 时间尺度 | 存哪 | 谁能看见 |
|---|---|---|---|
| 情绪 | 30 分钟半衰期 | `affect.json` → `emotion` | 她下一句话；面板「刚被戳到」 |
| 心境 | 8 小时跟随 | `affect.json` → `mood` | 注入的「心情不错/有点低落」 |
| 对书态度 | 天（每章更新） | `novel.json` → `books[url].attitude` | 弃书/重读；面板一行 |
| 念头 | 周月 | `novel.json` → `thoughts[]` | 注入「你这两天在想…」；可选进记忆 |

## 五、改动 A（P1）：读后评估 → 情绪

### A1 输出协议

反应 prompt 在现有基础上改**顺序**（先看到什么、再想到什么、最后才是感受），并要求一行机器可读的尾巴：

```
【正文】
你写完感想后，最后单独一行写：`[读:标签 强度 去留]`
标签：爽 / 触动 / 酸 / 闷 / 尬 / 烦 / 无感
强度：1（轻）2（中）3（重）
去留：继续 / 敷衍 / 想弃（可省）
感想里必须用「」引一段原文里的细节（三字以上），否则这段不算你读到的。
```

例：`……又是这种打脸桥段，饭都凉了。\n[读:烦 2 想弃]`

### A2 锚点校验（防表演）

`parseReaction(reply, chapterText)`：

- 剥掉所有 `[读:…]`，剩下的就是感想（`novel.json` 里仍然只存这一句，≤120 字）。
- 锚点 = 感想里第一个「」片段（去空白后 ≥3 字），在正文里做子串查找。
- 找不到时退一步：感想与正文是否有**连续 5 字**重合（4 字太容易撞「说道」「看着」）。
- 两样都不中 = **无锚点**：感想照存（那是她的话），但**不推情绪**。她说「好看」而引不出一句话，那多半是在演。

### A3 标签 → 情绪（数字全由宿主给，模型只报标签和 1~3）

| 标签 | v 愉悦 | a 唤醒 | d 支配 | 强度映射 |
|---|---|---|---|---|
| 爽 | 0.85 | 0.70 | 0.65 | 1→0.30 / 2→0.50 / 3→0.75 |
| 触动 | 0.62 | 0.45 | 0.42 | 同上 |
| 酸 | 0.36 | 0.50 | 0.30 | 同上 |
| 闷 | 0.28 | 0.25 | 0.35 | 同上 |
| 尬 | 0.25 | 0.55 | 0.35 | 同上 |
| 烦 | 0.16 | 0.65 | 0.48 | 同上 |
| 无感 | — | — | — | 不推 |

（爽 = 高愉悦高唤醒；触动 = 唤醒不高但浓度高；烦 = 有劲想吐槽，不是想哭——这几条分界和现有「羞/恼」「被凶/低落」的分法同一个思路。）

### A4 应用（host 侧，约十行）

`readNovelIfBored()` 在 `novelStore.save()` 之前：

```js
const r = parseReaction(thought, ch.text);
const emo = reactionEmotion(r);                    // 无锚点/无感 → null
if (emo && budgetLeftToday > 0) {
  const st = settle(store.load(), t);
  store.save(pushEmotion(st, emo, t));             // 情绪是真的动了
  budgetLeftToday -= emo.intensity;
}
```

- **日上限** `READING_EMOTION_DAY_MAX = 1.0`（累计强度）。80 章不能把心境钉死；一天最多两章「重的」有情绪，其余只是读。
- 读书**不碰** `relation`（不加温、不加信任）。
- 情绪标签会存进 `emotion.label`，注入的 `LABEL_HINT` 里要加这七个标签各一句（`inject.js:35`），否则标签等于没生效（那里有测试守着「每个标签都要能改变一句话」）。

### A5 注入改造

`novelLine` 从第三人称报告改成第一人称残留：

- 读过 <40 分钟且有标签：`你刚才自己在看《X》第 N 章「标题」，看得有点烦。当时想的是：「……」`
- 否则：`你 X 小时前自己在看《X》第 N 章「标题」。你觉得：「……」`
- 12 小时后整条不写（现状保留）。

### A6 面板

运行区那行从「在读《X》第 N 章」扩成：`在读《X》第 N 章 · 对这本：有点腻 · 上次：烦`。

### A7 顺手修的两个真 bug（2026-11-18 换源时实测）

- **广告行要按「行」洗**（三种都已实测）：
  - 顶点小说：`顶点小说 请记住我们的网址：www .x23us.us`（诡秘之主**每章**都有）、`二三中文全文字更新,牢记网址:m.23uswx.la`（宿命之环偶发）
  - 玄幻阁：`\\wＷｗ。 q Β5 .COM \．`（遮天第 1 章，夹在正文里）
  - 唐三中文网：`最新网址：m.xtangsanshu.info`
  规则：整行含 `网址|请记住|牢记|www|http|域名\\s*\\.\\s*(com|net|org|info|cn|us|la|me)` 就丢；再丢「短行且含站点名」（顶点小说/玄幻阁/笔趣阁/唐三/如书包/无双小说/醉读小说/吃鸡小说网）。宁可少一句，也别让她念广告。
- **占位短章会无限重试**：宿命之环第 1 章只有 127 字（「作者大大正努力存稿中…请重新刷新页面」）。现在 `<200` 字就 `return st` **不推进进度**，下一轮 `planRead` 又选中同一章 → 永远卡在这一章。改成：记 `skipped: [index]`，跳过并前进；同一本连续跳过 3 章 → 按「源坏了」换书。

### A8 查阅：`[书:]` 标记（默认源 = 顶点小说）

她想在聊天里翻回书里看某一段时用这个（和 `[查:]` 同一套 refine 机制，不是工具调用）：

| 标记 | 宿主做什么 |
|---|---|
| `[书:目录]` | 拉当前书的目录尾部：总章数 + 最近 10 章标题 |
| `[书:第12章]` | 按章号取正文，过 `cleanText`，≤3000 字 |

- 一轮最多一次，只读；取不到就如实说取不到。
- **默认源 = 顶点小说**：`PREFERRED_SOURCE = '顶点小说'`。10 本里 7 本在顶点，其余三本（斗破苍穹/放开那个女巫/神秘复苏）留在玄幻阁是因为顶点版不分段/缺章——所以「默认」实现成「优先用顶点、取书用书架里这本书自己的源」，**不写死源名**，写死反而会把那三本弄坏。
- **不跨源搜索**：`/searchBook` 的 HTTP 接口是坏的，真正的搜索是 WebSocket + App 访问令牌，没配。所以查阅只能查书架里已有的书。
- 提示词里告诉她这两个标记（`host.js:94` 那份协议清单加一行）。

## 六、改动 B（P2）：对书的态度 → 弃书 / 追更 / 重读

### B1 数据结构（`novel.json`）

```json
{
  "bookUrl": "...", "bookName": "...", "index": 12, "title": "...", "lastNum": 12,
  "readTitles": ["..."], "thought": "...", "at": 1730000000000,
  "readsDay": "2026-11-18", "readsToday": 3,
  "emotionDay": "2026-11-18", "emotionToday": 0.4,
  "books": {
    "<bookUrl>": {
      "name": "斗破苍穹", "reads": 12, "attitude": -0.18,
      "streak": 2, "lastLabel": "闷", "wantDrop": 0,
      "lastAt": 1730000000000,
      "finishedAt": 0, "droppedAt": 0, "dropReason": "",
      "reReadAt": 0,
      "recent": [{ "title": "第 12 章", "label": "闷", "intensity": 2, "thought": "……", "anchor": "……", "at": 0 }]
    }
  },
  "thoughts": [{ "text": "……", "at": 0 }]
}
```

`books[url].recent` 保留最近 5 条——它是「她对这本书的连续记忆」，要喂进下一次的反应 prompt。这是「越看越烦」能发生的前提。

### B2 态度更新

`updateBook(prev, reaction, now)`：EWMA，α = 0.15（最近几章权重高，但不会被一章洗白）：

| 标签 | Δ |
|---|---|
| 爽 | +1.0 |
| 触动 | +0.8 |
| 酸 | +0.55 |
| 闷 | −0.3 |
| 尬 | −0.6 |
| 烦 | −1.0 |
| 无感 | −0.2（无聊也是一种消耗，只是很慢：每章 −0.03） |

`streak`：标签是 尬/烦 或去留是「想弃」时 +1，否则归零。`wantDrop`：去留 == 想弃 时 +1，否则归零。

### B3 弃书判据（偏念旧）

```js
DROP_ATTITUDE   = -0.5   // 态度跌破
DROP_STREAK     = 5      // 或者连烦 5 章（连烦 5 章的态度也正好约 −0.55）
DROP_MIN_READS  = 3      // 前三章不判——开头难看很正常，念旧
DROP_WANT       = 2      // 她连着两次说「想弃」= 主动放弃，比态度更硬
```

「念旧」体现在三处：阈值偏松（不是 3 章就弃）、弃书前给满 3 章的宽限、**读完了优先重读喜欢的书**而不是立刻换。

弃书时记 `droppedAt` / `dropReason`（用她最后那句感想），**之后不再选这本**。她可以提起「那本我弃了」，那是真事。

### B4 选书顺序（`nextRead({shelf, books, state})`）

1. 书架里 `total === 0` 的**跳过**（现在坏源会白试一次）。
2. 上次那本没读完 → **continue**（一次只读一本）。
3. 上次那本读完了（目录到末尾）：
   - 态度 ≥ `REREAD_MIN = 0.3` → **reread**（从头再读，`reReadAt` 记录，同一本最多重读一次）
   - 否则 → 换一本**没读过**的（挑态度最高/最久没碰的）
4. 全读完/全弃了 → **wait**（追更）：不发模型调用、不推情绪，只记一次 `waitingAt`。
5. 书源目录刷新出新章（`chapters.length` 超过她读到的）→ 清掉 `finishedAt`，继续读。

### B5 顺手治两个病

- **0 章书**：`shelf` 里 `total === 0` 的不进候选（现在会浪费一次拉目录）。
- **读完从头循环**：`planRead` 的第三条（`novel.js:67`）保留给「重读」，但只有 `reread` 动作才允许走进它；普通读取到目录末尾就停，进 wait/换书。

## 七、改动 C（P3）：记忆与念头

### C1 强感触进记忆卡

条件：有锚点 且（强度 3，或标签 ∈ {触动, 酸} 且强度 ≥2）。

```js
remember(card, `看《${book.name}》${title}，看到「${anchor}」，${thought}`, {
  source: 'seen',            // 真实发生：她真的读到了这一段
  heat: Math.min(0.6, intensity / 4),
  mood: 当时的 emotion,
})
```

热度封顶 0.6：读书是「她自己的事」，不该和他说的话抢记忆权重。这样几天后聊到「等」「退婚」之类的词，它自己会浮上来——**这才是「感触」和「读后感」的区别**。

### C2 每天一次的「想一想」

`thinkIfBored()`，和读书一样不进串行队列，有 `thinking` 闸：

- **闸**：安静 ≥ `BORED_QUIET_MS`；今天还没想过（`thoughtsDay`）；**有真材料**——今天有 ≥1 条非无感的反应，或某本书态度变化 ≥0.15。没材料就不问，空着比硬凑好。
- **输入**：最近 3 条反应（书名/章/标签/锚点/感想）+ 当前状态一句话 + 弃过的书。
- **输出**：≤100 字，可以是书里的人、一句话、或「我为什么烦」。**允许回「没有」**，回了就记下今天想过了，不再追问。
- **存**：`thoughts[]` 保留 20 条；强念头（≤100 字且提到具体细节）再写一张 `source: 'inferred'` 的记忆卡——`inferred` 的根是「她自己想的，不许冒充事实」，这正是它的用途。

### C3 念头注入

`thoughtLine(state, now)`：最近一条念头 36 小时内 → `你这两天自己在想：「……」`。和 `novelLine`/`bookLine` **同时只出一条**（优先级：念头 > 对书态度 > 读到哪），免得一轮注入三条读书内容。

### C4 品味

v1 **不做** genre/标签分类。等有 20 章真实反应之后再看 `recent` 的分布，那时候才知道她到底吃哪一类；现在设计味型就是拍脑袋。

## 八、防假闸门（清单）

1. **锚点强制**：引不出原文细节的反应不推情绪。
2. **允许无感**，且无感是常态；全章「好感动」等于没有情绪。
3. **数字全由宿主定**：模型只报标签和 1~3，不报 v/a/d。
4. **读书不加关系分**：不涨亲密、不涨信任。
5. **日上限**：读书情绪累计 ≤1.0/天；读完的书不重复推同一条情绪。
6. **不许编更新**：追更只看目录真实长度。
7. **同一件事不重复注入**：念头/态度/在读三选一。

## 九、参数表（「偏念旧」）

| 名 | 值 | 说明 |
|---|---|---|
| `READS_PER_DAY` | 80 | 闸，不动 |
| `READ_GAP_MS` | 10 min | 不动 |
| `BORED_QUIET_MS` | 2 h | 不动 |
| `ATTITUDE_ALPHA` | 0.15 | 每章权重 |
| `DROP_ATTITUDE` | −0.5 | 弃书态度线 |
| `DROP_STREAK` | 5 | 连烦 5 章 |

## 十一、测试（不联网）

1. `parseReaction`：正常尾巴 → 标签/强度/去留；无尾巴 → 无感且感想保留；尾巴被剥干净。
2. 锚点：引文命中 → `anchored`；改一个字 → 不命中；无引号但共享 5 字 → 命中。
3. 锚点失败 → `reactionEmotion` 返回 null（不推情绪）。
4. 七个标签 → v/a/d 与强度映射逐个断言；无感 → null。
5. `updateBook`：连烦 5 章的 attitude 单调下降并触发 `shouldDrop`；连爽 3 章 > 0.3 且不弃；连無感 10 章只缓慢下降。
6. `shouldDrop`：`reads < 3` 永不弃；streak 5 弃；想弃两次弃。
7. `nextRead`：空书架 → none；0 章书跳过；同一本未完 → continue；读完且态度高 → reread 且 `planRead` 从头；读完且态度低 → 换未读；全完成 → wait；弃过的不再选。
8. 日上限：三次强反应，累计超过 1.0 之后不再推，情绪不炸。
9. `novelLine`：<40min 带标签且第一人称；>12h 空。
10. `bookLine`：只在 |态度| ≥0.2 时产出。
11. `thoughtLine`：36h 内产出；过期空；与 `novelLine` 互斥。
12. host 端到端（假 fetch + 假 `complete`）：读完 → `affect.emotion.label` 写入；强反应 → 记忆卡有 `source: 'seen'`；`novel.json` 有 `books[url]`。
13. host：无锚点的反应 → 情绪不变、感想仍存。
14. `thinkIfBored`：没材料 → 不调用模型；有材料 → 写 `thoughts` 且当天不再问；回「没有」→ 不写。
15. 回归：现有 572 条全过；`planRead`/`noteRead` 的旧行为不变（旧状态文件没有 `books` 也能读）。

## 十二、验收（可观察）

| 阶段 | 怎么验 |
|---|---|
| A | 强制读一次（测试或面板按钮）→ `affect.json` 的 `emotion.label` ∈ 七标签、`intensity > 0`；下一句回复可见地变短/变冲；面板出现「刚被戳到」 |
| B | 用测试模拟连烦 5 章 → 该书记录 `droppedAt` 非空、`dropReason` 是她最后那句话；下一次读换了另一本 |
| C | 强感触后 `memory.json` 出现 `source: 'seen'` 的读书记录；注入里出现「你这两天在想…」；`thoughts` 一天最多一条 |

跑两周后看 `novel.json` 的 `recent` 标签分布：**爽 ≥60% 说明闸门失效**（模型在演），要回来调 prompt；`无感` 占一半是正常的。

## 十三、顺序与工作量

1. **A（约半天）**：地基，体感立刻能验。做完就能回答「爽点会不会爽」。
2. **B（约一天）**：态度与弃书。做完才能回答「读多了会不会反感」。
3. **C（约半天到一天）**：记忆与念头。做完才有「思想」。

A 不做完就做 B/C，等于在不会动的情绪上盖楼。

## 十四、风险

- **模型仍爱演**：锚点闸会砍掉一部分真反应。这是诚实的代价——宁可少感动，不要假感动；砍太多就把「连续 5 字」降到 4 字。
- **标签分布漂移**：全「爽」= 失效。所以 `recent` 要留着给人看，跑两周统计一次。
- **读书和「他不在」绑死**：他一天到晚聊，她就不读书，也就没有感受。缓解：`BORED_QUIET_MS` 先不动（2h），观察一周再决定要不要降到 90 分钟。
- **弃完没书读**：现在只有 6 本可用。她弃 2 本就进入 wait。所以**修书源**（手动换源）和这条并行，不是可选项。
- **重读循环**：态度高就重读，可能反复读同一本。缓解：同一本最多重读一次，`reReadAt` 后不再重读。
- **想一想变成空话**：模型会写「我在想人生」。缓解：只喂真反应、允许回「没有」；一周后看念头有没有具体细节，没有就砍掉这一层只留 A/B。

## 十五、我拍的小决定（不同意就说）

- 标签就用七个，不做多维度组合。**先观察 20 章真实反应再加。**
- 强度只给 1~3，不给 0~100：细数字是假的，粗档才诚实。
- 数字全由宿主映射，模型只给标签。
- 回应 prompt 顺序改成「看到什么 → 想到什么 → 感受」：顺序一换，表演味掉一半。
- 「无感」也记进态度（慢速下降）：无聊是消耗，只是很轻。
- 想一想允许回「没有」，且回了就记下当天问过——**不被追问的东西才是她自己的**。
- 不做 genre/品味分类，等真实分布。
- 读书永远不给关系加权。
