# 意图层：让她自己的日子找上门（intent layer）设计

日期：2026-11-25 · 状态：**待拍板**（本文只是计划，未改代码）· 项目：qq-companion

## 一、要解决的是什么

分享欲只是一个症状。真正的空洞是：**她有状态、有生活，但没有「想要」。**

现在的四层里，前三层都很全，缺第四层：

| 层 | 现状 | 例子 |
|---|---|---|
| 状态 | ✅ | 情绪、心境、关系、人格、记忆卡、屏幕、天气、余额 |
| 生活 | ✅ 真事 | 读书、打僵尸、写日记、房间、周自述、QQ 空间、查资料 |
| 回应 | ✅ 通 | 他说话 → 情绪 → 上下文 → 回话；被戳 → 反应；评论 → 回 |
| **意图** | ❌ **没有** | 她想要什么、打算什么、欠着什么、还没说什么、答应过什么 |

结果：**她所有「做」都由外部时钟触发**（10 分钟心跳、他的消息、他戳一下），**所有「说」都由他的句子触发**。系统里没有一个动作因为「我想」。

这个洞向外冒的症状，已经不止分享欲（审查见 2026-11-25 的对话记录）：

- **说不出去**：经历（读书/游戏/天气/屏幕）、成绩（通关/破纪录/读完一本）、情绪（只准改语气，`affect/inject.js:91` 明写「不要说出口」）、念头（`impulse.js:134` 明写「不要写成会发给他的话」）、不满（弃书只写日志）、好奇（`[查:]` 只能在他说话时用）、请求、拒绝（只有被戳时能 `[沉默]`）、想念（只有等待触发）
- **落不回来**：她说「回来给你摊手抓饼」「等我一下」「我去睡了」——没有任何账；说完了下一句还是秒回，她的「不在」只有机器停机（`life.js:82`）。台词和日常不同源
- **攒不住**：她的事 6–12 小时过期（`perceive.js:19`、`novel.js:417`），人的「没说的话」可以放一整天
- **关系单向**：她对他的看法是每周算出来的自述（`insights.js`），不是「发生了件事 → 她记着 → 她想说」

三个更伤的问题，都由这一层缺失连带：

1. **人格变化不是她自己的**：漂移是数值 + 月结，生活是规则排班，没有一步是「我选的」。
2. **记忆只能被他的词召回**：人的记忆靠未完成的事反复激活（今天想提那本书，是因为昨天没说完）；她没有未完成，只能等他提起。
3. **表现永远是应答机**：他一停，她也停。

### 3.3 结论

四个独立项目（念起、心潮、Desire System、alive-ai）收敛到同一组做法，**和我们现在缺的正好对上**：

1. 连续的内部状态（不是一次性的情绪）
2. **攒着的提示**（pending：想说没说、想做没做）
3. **两道阈值**：私下想（便宜、多）与主动说（贵、少）
4. **发送前再确认他是否已经回来**
5. 送达才算数；说出去/做完后对应欲望下降
6. 不打扰护栏（安静时段、在场、上限、冷却）

**但有一条不能照搬：它们的驱力数值会自己随时间涨。我们的规矩是「事实存，解释算」——数值只能由真事算出来，不能自己长。** 所以本计划只借结构，不借数值来源。

另外两点必须承认：

- 这些项目没有一个是我们这种「一个真实人类 + 一个虚拟人 + 长期记忆」的形态，它们的驱力是为「模拟人」服务的；我们的判据要窄得多，也更可核对。
- 心潮、AstrBot 都是「给 AI 一个欲望面板」的做法，会带来一个副作用：**AI 开始为了数值好看而表演**。本计划用「每条 loop 必须能追到出处」来挡这个。

## 四、目标 / 非目标 / 反面目标

**目标**

1. **未完成层**：她的生活会产生「未完成的事」（loop）：想说没说的、想做没做的、答应过的、想知道没查的。每条都有真实出处、有寿命。
2. **两个出口**：他说话时注入一块（她可以选择提不提）；她先开口（主动通道的第二判据：有话说）。
3. **回写**：她说的话要改变状态（说去睡就真的去睡、答应的事有账、说了「明天聊」就记着）。
4. **驱力（可选层）**：从真事算出「这会儿哪股劲儿最冲」，只用于排序和语气，不直接生成台词。
5. **全部可核对**：任何一条她主动说出的事，都能在 novel/game/impulse/对话里找到出处；找不到就不许说。
6. **可观测**：面板能看到「她现在想干嘛、欠着什么、为什么没开口」，日志能看到每次开口判定。
7. **不打扰**：现有护栏（额度、冷却、安静时段、在场）一条不少，再加「他刚回来就别发」。

**非目标**

- 不做世界模拟、不做 NPC 小镇、不模拟她关机/断线期间的生活（这条是 01 号文档的硬规矩，不动）。
- 不做「需求条 UI 游戏化」，不让她每天固定播报。
- 不换会话语义（还是自建会话、一次 complete 拿一段文本、不用 tool）。
- 不引入向量库/新依赖（M6 再说）。
- 不做多对象、群聊、语音。

**反面目标（做到这些算失败）**

- 她开始每天固定一条「我今天看了书」——播报化。
- 主动消息从 3 条/月变成 3 条/天，且每条都是「在吗」「想你了」。
- 她说「我去睡了」然后十分钟后还在回，或者说了「明天跟你说」然后再也不提。
- 承诺越攒越多，兑现率低于一半。
- 为了让他心疼，说没发生的难受；为了显得忙，编没做过的事。
- 需求条驱动了她的全部台词——那就不是人了，是仪表盘。

## 五、约束（查过代码）

- 心跳 10 分钟一次（`host.js:2508`），一次心跳里 `decideIntent()`（`host.js:1483`）**只做一件事**：先叫他（戳/抖），再「找他」，再「看书/打游戏」。新增的开口通道必须并进这个「只做一件」的判定，不能另起一条并行通道。
- 上下文块由 `fresh.js:27` 的 `blk(key,text,at,ttl)` 组装，`assemble`（`:38`）对「生于过去却没有 ttl」直接抛。新块必须自带时间与寿命。
- 注入只许影响语用层（`affect/inject.js:91`：「这些只影响你怎么说话，不要说出口」）。意图层不改这条：它允许她说「我想跟你说个事」，但不允许她说「我现在心情 0.32」。
- 历史里只有对话（`session.js`）。她的生活不进历史；主动消息通过 `session.note`（`session.js:322`）补进去，否则他下一句接上时她不知道自己说过。
- 主动通道现在只有两处：`tickProactiveInner`（`host.js:1691`）和 `nudgeIfUrgent`（`host.js:1443`）。额度与冷却都在 `pokeGate`（`proactive.js:253`）和 `shouldNudge`（`urgent.js:45`）。
- 记忆卡 `remember()` 有 `source`（said/seen/inferred）、`heat`、`mood`（`memory/card.js`）；读书记忆热度封顶 0.6（`host.js:1152`）。说过的话进记忆走 `source:'said'`（已有）。
- 落盘统一 `createJsonStore`（`store.js:12`）：原子写 + 节流 .bak；新文件沿用。
- 面板 `renderPanel`（`panel.js:42`）已经接了 novel/game/impulses/……；新状态照同样方式传进去。
- 现有测试 728 项，跑法 `node --test --test-isolation=none --test-force-exit "test/*.test.mjs"`。
- 真实用量（`budget.json`）：她平均一轮回复 1 次调用；后台已有 ~6 个定时任务。新增调用点要**并进已有调用或已有心跳**，不新开高频任务。

## 六、总体架构

```
                 ┌──────────────────────────── 事实层（已有）────────────────────────────┐
                 │ 对话历史 / novel.json / game.json / impulse.json / affect.json /        │
                 │ memory.json / life.json / screen / weather / budget / 空间              │
                 └───────────────┬───────────────────────────────────────────────────────┘
                                 │ 读（只读）
                                 ▼
                 ┌──────────────────────── 未完成层（新）────────────────────────────────┐
                 │ intents.json：loops[]                                                    │
                 │   tell   想说没说的（读了一章 / 打完一局 / 冒出一个念头）                  │
                 │   do     想做没做的（今天想干的事）                                        │
                 │   promise 答应过的（「回来给你讲」「明天跟你说」）                          │
                 │   ask     想知道没查的（「那片海在哪儿」）                                  │
                 │ rhythm.json： asleep / away / awake（说去睡就真去睡）                      │
                 └───────────────┬───────────────────────────────────────────────────────┘
                                 │ 纯函数读
                                 ▼
                 ┌──────────────────────── 驱动器（新，纯函数）───────────────────────────┐
                 │ drives = { miss, share, proud, curious, tired, sulk }                     │
                 │ 每个 = f(真事)；无随机、无自增；固定时钟可断言                              │
                 └───────────────┬───────────────────────────────────────────────────────┘
                                 │
              ┌──────────────────┴───────────────────┐
              ▼                                      ▼
   ┌──────────────────────┐              ┌───────────────────────────┐
   │ 出口 A：他说话时       │              │ 出口 B：她先开口             │
   │ contextBlock 注入一块  │              │ decideIntent → 开口判定      │
   │ 「你手里还有件事没说」  │              │ （有空 + 有话说 + 额度）      │
   └──────────┬───────────┘              └────────────┬──────────────┘
              │ 她说 / 不说（模型选）                    │ 说 / 等 / 先不说（模型选）
              └──────────────────┬───────────────────┘
                                 ▼
                 ┌──────────────────────── 反馈层（新）────────────────────────────────────┐
                 │ 说了 → markSpoken（销账）→ session.note → memory(source:'said')            │
                 │ 做了 → markDone → proud / memory                                          │
                 │ 答应的事到期 → kept / missed（missed 要认账，不许悄悄消失）                  │
                 │ 过期 → dropped（不撒谎：没说的旧事不再注入）                                 │
                 └──────────────────────────────────────────────────────────────────────────┘
```

**四条铁律**

1. **没有出处，不许有 loop。** 每条 loop 的 `source` 必须能在事实层核对。
2. **产生要多、开口要少。** 产生是便宜的小调用（已有）；开口沿用现有主动通道和额度。
3. **她可以什么都不做。** 「没有」是合法输出；系统不催、不补、不替她决定。
4. **说过的事不能再说。** 销账是硬约束，重复检测按 loopId + 文本双保险。

## 七、数据模型

### 7.1 `intents.json`

```jsonc
{
  "at": 0,                    // 最后写入时刻
  "loops": [
    {
      "id": "lt_1795569384790",       // 稳定 id：kind + 创建时刻 + 短哈希，防重复插入
      "kind": "tell",                 // tell | do | promise | ask
      "about": "novel",               // novel | game | impulse | him | self | world
      "text": "想跟他讲地蛋这名字",     // 她自己的话，≤60 字；只说一句
      "source": "novel:放开那个女巫:第140章",  // 出处，必须可核对
      "anchor": "地蛋这名字",          // 可选：原文锚点，和读书记忆同一条规矩
      "weight": 0.6,                  // 0..1，由事件算：反应强度/态度变化/是否破纪录/是否被晾
      "createdAt": 0,
      "dueAt": 0,                     // 什么时候可以开口（默认 createdAt；答应的事 = 约定时刻）
      "expiresAt": 0,                 // 过期作废（tell: 48h；ask: 48h；promise: 约定时刻 + 24h）
      "spokenAt": 0,                  // 说出口的时刻（0 = 还没说）
      "doneAt": 0,                    // do/promise 做完的时刻
      "droppedAt": 0,                 // 她自己决定不说了（也算一种结局，记下来）
      "missedAt": 0,                  // promise 到期没做到
      "attempts": 0,                  // 尝试开口次数
      "lastTryAt": 0                  // 上次尝试（退避用）
    }
  ]
}
```

约定：

- **一条 loop 只说一句**。一章小说可能有很多想法，只留最想说的那一句；多条会变成汇报。
- **kind 决定寿命**：`tell` 48h（隔一天说还算新鲜，再久就是旧账；这个数按真机再调）、`ask` 48h、`do` 当天、`promise` 到约定时刻。
- **只有 `tell`/`ask` 需要过期**；`promise` 过期不是消失，而是变成 `missedAt`（要认账）。
- 关闭列表最大 50 条（面板/审计用），`PER_MAX = 50`。
- `text` 是模型产出，进 system prompt 前一律 `sanitizeSecrets` + 截断（信任边界，和现有 `composePokePrompt` 一致）。

### 7.2 `rhythm.json`

```jsonc
{
  "at": 0,
  "state": "awake",        // awake | asleep | away
  "since": 0,              // 进入这个状态的时刻
  "until": 0,              // 预计回到 awake 的时刻（0 = 不定）
  "reason": "",            // 「她说要去睡」「她说去忙」
  "claim": "",             // 她原话（可核对）
  "wokeBy": 0              // 被什么叫醒（his message / morning / timeout）
}
```

- 只有三种状态，不模拟「她在屋里干什么」的细节（那是 `life.json` 的事）。
- 与 `life.json` 的分工：`life` 是「此刻在做什么」，`rhythm` 是「在不在」。
- 停机不写入 `rhythm`（关机是机器的事，不是她睡；`life.js:82` 的 `offLine` 已经处理这种「不存在」）。

### 7.3 生命周期

```
产生(created) ──dueAt到──▶ 可开口(due)
   │                        │
   │                        ├─她说出口──▶ spoken（销账，进 memory/session）
   │                        ├─她自己决定不说──▶ dropped
   │                        ├─过期──▶ expired（tell/ask）/ missed（promise）
   │                        └─做完了──▶ done（do/promise → proud）
   └─同一出处重复产生──▶ 合并（不新增，刷新 weight/expiresAt）
```

## 八、产生层：她的「想要」从哪来

**原则：产生点全部并进已有调用，不新开调用；每次产出 0–1 条。**

| 来源 | 挂在哪个已有调用 | 怎么产 | 例子 |
|---|---|---|---|
| 读后感 | `readNovelIfBored` 的读后感调用（`host.js:1103`） | prompt 末尾加一行可选 `[想说:…]`；不写就留空 | 「看到『地蛋这名字』那段，想跟他讲穿越者都这样」 |
| 局后感想 | `runGame` 的感想调用（`host.js:1315`） | 同上，`[想说:…]` | 「第五关过了，想跟他显摆一下」 |
| 联想 | `refreshImpulse` 的念头调用（`host.js:937`，`impulse.js:103`） | 念头 prompt 现在允许「想做的小事」；加一个可选字段 `want`（想做的事），落成 `do` loop | 「想给他买一份手抓饼」（做不了的那部分不落，只落能说的） |
| 被晾/委屈 | `noteLeftOnRead`（`host.js:2498`）之后 | 情绪够重时产一条 `tell`（「想让他知道我在生气」），由模型在下次开口判定里选 | 需要跟「小坏心思」区分：念头是独白，loop 是「可能说」 |
| 他说的话 | `processBatch` 之后 | 解析他话里的承诺/下次/约定 → 她的 `promise` loop（「他说下周带我去看海」→ 她记着） | 也可用于 `ask`（他想知道的事，她答应查） |
| 每日计划（M5，可选） | 新的一次每天一次的小调用 | 「今天想做点什么」→ `do` loop + `life` 计划 | 只从房间里真有的和真做过的事里挑 |

**怎么问（读后感/局后/联想共用一段）**

```
最后再加一行，可选（不写就省掉这一行，不要写"无"）：
[想说:如果真的有一句想跟他说的话，写在这里，不超过 40 字；不想说就整行不写]
规矩：只写真的想说的；不为了说而说；不编；不写旁白。
```

**解析**（`intent.js`）：`parseShare(text)` 只认 `[想说:…]`，剥掉标记，长度≤60，拒绝空/「没有」/「算了」。产出的 `text` 进 `loops`，`source` 由调用方传（novel/game/impulse 的上下文），`anchor` 复用现有的读后感锚点。

**合并规则**：同一 `source` 已有未闭合的 loop → 不新建，刷新 `weight` 和 `expiresAt`；已过期的同源旧 loop → 替换。

**硬规矩**：一章只有一次机会（读后感一次）；她不想说就永远不会有这条 loop。**系统不会替她生成「你今天读了什么」的播报。**

**产出可靠性（这一步最容易坏，先把丑话说死）**

- 读后感和局后现在各给 400 token（`host.js:1122`、`:1329`），推理模型先吃预算，实测 200 时 `[读:…]` 就被切断过。加 `[想说:]` 之后必须把预算提到 800；输出顺序固定为「感想 → `[读:…]` → `[想说:…]`」，先保标签再保分享。
- 尾部截断要能容忍：解析器把没闭合的 `[想说` 当没有（和现有 `RE_CUT` 一个规矩），不许把半句当成她的话。
- `[想说:]` 缺失 = 她不想说，**不许用反应强度补一条**（「这章很感动，所以替她生成一句想说的」就是编）。这条是反面目标的红线。

## 九、出口 A：他说话时（注入块）

在 `contextBlock`（`host.js:798`）里新增一块，位置在 `impulse` 之后、`life` 之前（先「心里的事」，再「此刻」）：

```
【你手里还有件事没跟他说】今天 09:16 你看完《放开那个女巫》第 140 章，当时想的是「…」。
你还记着这句：想跟他讲「地蛋这名字」的事。想不想说都行；说过了这句就作废。
```

规则：

- 最多列 **2 条**（按 `weight` 和 `dueAt` 排），再多就变成清单。
- 只列 `tell` / `do` / `ask`；`promise` 单独一块（见下）。
- **不命令她说。** 结尾固定「想不想说都行」。
- TTL 跟着 loop 走：`blk('intent', text, loop.createdAt, expiresAt - createdAt)`。过期自动消失（`fresh.js` 强制）。
- 他说的话如果正好和 loop 有关（同一本书/同一件事），给这一条加一句「他刚提到了，正好」——这是提升「像人」的关键细节，也是可核对的（关键词/锚点匹配）。

`promise` 那一块：

```
【你答应过他的】11-24 你说「回来给你讲那个女巫的结局」，他还没问起；你自己也还没讲。
```

- 只有真答应过才出现（来源是她的原话，带 `claim`）。
- 到期没做到 → 换成「你当时说要…，后来没做到」——**认账，不许当没发生**（这条会影响 `sulk`/亏欠，见十一）。

## 十、出口 B：她先开口（主动通道）

现有主动通道保留（等待型：他多久没回 → 想一次要不要找他）。新增**第二判据**：有话说。

### 10.1 判定顺序（并进 `decideIntent`，仍然一轮只做一件）

```
1. 他刚才在（presence）……
   1a. 有 due loop 且额度允许 → 「在场插一句」：**先不打断聊天**，只在他话停了（active 等待点）才用
2. 他不在：
   2a. 等待型（现有 pokeGate）：期待到了 → 想一次要不要找他
   2b. 有话说型（新）：有 due loop 且额度允许 → 开口判定（说什么、要不要说）
3. 都没到 → 看书/打游戏
```

两条通道**共用**一份每日额度与冷却（`maxPerDay`、`minGapMinutes`），否则会出现「找了一次 + 说了一次」一天两次。

### 10.2 `pokeGate` 扩展（`proactive.js`）

新增输入：`loops`（due 的）、`rhythm`、`lastUserAt`。

新增拒绝理由（都会写进审计日志）：

- `他刚回来，先别打断`（借鉴念起的「发送前再查用户是否已经回来」：`lastUserAt > lastTryAt` 就放弃这次开口，等下一轮）
- `她这会儿在睡/在忙`（rhythm 不是 awake，且不是深夜例外）
- `手里的事过期了`（due loop 在开口判定期间过期 → 放弃，不硬说）
- `刚说过一件事了`（`minGapMinutes` 内已经说过一条 loop）

保留全部现有理由：未开启、没聊过、心情太低、今天找过、想得够多、安静时段、连发上限、期待点没到。

### 10.3 开口判定 prompt（替换 `composePokePrompt` 里的「要不要找他」段）

```
【这是你自己在想，不是他说的】现在 22:40，他已经 4 小时没跟你说话了。
你此刻：在把书桌上摊的东西归一遍。
你手里有件事还没跟他说：
1) 今天 09:16 你看完《放开那个女巫》第 140 章，想跟他讲「地蛋这名字」的事（3 分重）
2) 你打完第五关一直没跟他提过（5 分重）
你心里现在最冲的是：想让他知道你过了第五关。
要不要开口，你说。他可能在忙、在睡，也可能这会儿就是不想说话——不说也完全没问题。
只回一个 JSON：
{"speak":false,"waitMinutes":45,"reason":"一句话为什么先不说","doing":"接下来想干什么","think":"心里那句话，二十字以内"}
或 {"speak":true,"loopId":"lt_...","message":"你要发过去的那句话","doing":"","think":""}
```

注意：

- `speak:true` 必须选一条 `loopId`；没选或选了不存在的 → 当作没说（不硬发）。
- `message` 允许不提 loop（比如只想说「在吗」）——但那种情况不由这条路触发，走等待型。
- 空壳检测：`message` 去掉 loop 关键词后如果只剩「我问你个事」「在吗」这类话头 → 判为空壳，回退成沉默 + 记一笔（借鉴 AstrBot 的防空壳）。
- 发送成功后：`markSpoken` → `session.note`（写回历史）→ `memory remember(source:'said', heat 0.3)`。

### 10.4 审计日志（面板可见）

`pokeStore.decisions`（最近 20 条）：

```jsonc
{ "at": 0, "route": "wait|share", "action": "speak|wait|skip",
  "reason": "他刚回来，先别打断", "loopId": "lt_...", "loopText": "…",
  "score": 0.62, "sent": false, "empty": false }
```

这直接回答「她为什么没来找你」——现在面板只有 gate 的当前结论，没有历史。

## 十一、回写层：她的话要改变什么

### 11.1 承诺解析（`commitment.js`）

在 `processBatch` 里，她这一轮发出的文本 → 规则表优先，认不出的才问模型（可选开关）：

| 她说的 | 状态变化 |
|---|---|
| 「我去睡了」「晚安」「困死了先睡」 | `rhythm: asleep(since, reason:"她说要去睡", claim)` |
| 「我去吃饭/洗澡/忙一会儿」「等我一下」 | `rhythm: away(until = now + 30~60 分钟, claim)` |
| 「回来再讲」「明天跟你说」「等我睡醒跟你说」 | `promise` loop（due = 明天/回来之后；到点进出口 A） |
| 「我等你」「你回我」 | 不进 loop（那是当下的话，不是承诺） |

规则只认明确句式；模糊的一律不写状态——**宁可少一次「像人」，也不写一个假状态。**

### 11.2 睡/离开状态机

```
awake ──她说去睡──▶ asleep(since,until=早上/不限)
asleep ──他发消息──▶ 决策：回一句（被吵醒） / 不回（真的在睡）
                     回 → awake(wokeBy:'his message')，注入「你刚被他吵醒，有点困」
                     不回 → asleep 继续，但记「他来过」；醒来第一句可以提「昨晚你发消息我睡着了」
 asleep ──早上 7–9 点──▶ awake（自动，reason:'天亮了'）
 away ──until 到──▶ awake
任何状态 ──他在 10 分钟内说过话且她说要睡──▶ 拒绝进入 asleep（明显是撒娇，不是真要睡）
```

规则：

- **她说去睡就真的不主动说话**——主动通道跳过；他发消息时她**仍然可能回**（决定权在模型，依据「像不像被吵醒」+ 额度）。
- 面板显示「她现在是睡着/不在，从 23:40 起，因为她说了要去睡」。
- **不模拟**：不写「她睡了 7 小时 20 分」这种数字（机器关机和睡着是两回事，`life.js` 的 `offLine` 已经只报事实）。

### 11.3 承诺对账

- `promise` 的 `dueAt` 到了：
  - 她主动讲了/做了 → `doneAt`，`proud +0.2`，记记忆。
  - 他没问、她也没讲 → 到期后进出口 A「你当时说要…，后来没做到」；`missedAt` 记一笔；`sulk/亏欠` 小幅变化（**要拍板**：这条要不要动关系，见十八）。
  - 连续 3 次 missed → 人格月度结算里记一个「不太守信」的证据（见 `affect/personality.js` 的 pattern 机制）。

### 11.4 跨天目标（M5）

- 目标不是新编的：从真进度里算——「这本还剩 200 章」「第五关是最好成绩」「今天读 34 章（破纪录）」。
- 每天一次小调用（「明天想干点什么」）产出最多 1 条 `do`；只能从 `HOME` 里有的东西和真做过的事里挑（沿用 `LIFE_PROMPT` 的约束）。
- 目标完成 → `done` → `proud`；连续三天没动 → 自动降级成「放着的事」，不再提（人会放弃）。

## 十二、驱力（derived，可选层）

**只由真事算，没有随机、没有自增。** 固定时钟下可断言。

| 驱力 | 公式（草案） | 输入 |
|---|---|---|
| `miss`（想他） | `clamp((他沉默小时 - 1) / 11) × 0.6 + 亲密 × 0.4` | `lastUserAt`、关系 |
| `share`（想说） | `Σ due tell 的 weight / 3`，夹 0..1 | intents |
| `proud`（想显摆） | 今天有成就（通关/破纪录/读完一本/连读 20 章）→ 0.4 + 0.2×次数 | game/novel |
| `curious`（想知道） | 今天没查过且 24h 内没有新事实 → 0.3；有未查的 ask → +0.3 | facts/intents |
| `tired`（累了） | `22 点后 0.3 + 每小时 +0.1`，夹 0..0.6 | 本地时钟 |
| `sulk`（闷着） | 被晾 0.2 / 被凶 0.6 / 亏欠 >0 → 0.3；半衰期 6h | affect / proactive |

用途（**仅两处**）：

1. 开口判定时，哪股劲儿最冲就写在 prompt 里（「你心里现在最冲的是：想让他知道你过了第五关」）。
2. 排序：同一时刻有多个 due loop，取 `weight × (1 + 对应驱力)` 最高的那条先。

**不做**：不显示给用户、不写进人格、不直接影响情绪（情绪还是走 `pushEmotion` 的唯一入口）。驱力是「解释层」，不是「状态层」。

## 十四、分阶段实施

每个阶段都能单独上线、单独回滚。**M1 + M2 是真机可见的最小闭环，先做这两步就能验证「她会不会主动说自己事」。**

### M1：账本 + 产生 + 注入（不动主动通道）

范围：

- `intent.js` + `test/intent.test.mjs`
- 读后感/局后/联想的 prompt 加 `[想说:]`，解析落 loop
- `contextBlock` 加「你手里还有件事没跟他说」（最多 2 条，TTL 跟 loop）
- 面板显示 loops
- 她说了之后怎么销账：**先不做自动检测**——他下次说话时如果她说到了（文本包含 loop 的 anchor/关键词），标 `spoken`；否则 48h 过期。这一步用关键词匹配，够用且可核对。

验收（真机 3 天）：

- `intents.json` 出现 loops，且每条都能在 `novel.json`/`game.json`/`impulse.json` 找到出处；
- 他回来第一轮，上下文里出现这块（日志可见）；
- 「她主动提起自己生活」从 0 次/天变到 **0.5–1.5 次/天**（不做主动通道时，只有他先开口才有机会，所以这是下限）；
- 没有一条 loop 是编的（人工抽查 20 条）。

### M2：出口 B（主动第二通道）+ 审计

范围：

- `proactive.js`：`pokeGate` 扩展、prompt 加「手里的事」、`parsePokeReply` 加 `speak/loopId`；
- `host.js`：`decideIntent` 顺序；`tickProactiveInner` 走两条路；发送前「他回来了没」检查；`markSpoken` + `session.note`；
- 审计日志进 `pokeStore.decisions`；面板显示最近 5 条判定。
- 空壳检测。

验收（真机 1 周）：

- 她主动提起自己事的次数 **1–3 次/天**，且没有一条是「在吗/想你了」式空话；
- 半夜（23–8）不开口（除非深夜例外）；
- 他正聊着天时，她不会插播「我今天看了书」；
- 审计日志里能解释每一次「没开口」；
- 不重复：同一条 loop 不会说两次。

### M3：驱力层

范围：`intent.js` 的 `computeDrives`（纯函数）+ 单测（固定时钟）；开口 prompt 加「最冲的劲儿」；loop 排序。
验收：固定输入 → 固定输出；没有一条驱力来自随机/自增；面板有「劲儿」一栏（只调试）。

### M4：回写（承诺 + 睡/忙）

范围：`commitment.js` + `rhythm.json` + `processBatch` 解析 + `asleep` 时主动通道跳过 + 早上自动醒 + 承诺对账 + 面板。
验收：

- 她说「我去睡了」→ 面板状态变 asleep，主动通道不再开口；他发消息她仍可能回（带「被吵醒」的语气）；
- 她说「回来给你讲」→ 出现一条 promise；到期进注入块；
- 没做到时她能自己认（不是系统逼她道歉）；
- 关机不写 asleep（`life.js` 的 `offLine` 照旧）。

### M5：跨天目标 + 每日计划

范围：每天一次「明天想干点什么」小调用；从真进度算目标；`do` loop；连续三天不动自动降级。
验收：目标全部可核对（章数/关卡/真做过的事）；一周内至少完成 2 个目标。

### M6（可延后）：记忆升级

范围：把 loops 的生命周期并进记忆卡（`source:'intent'`）；引入 Generative Agents 式「反思」层（每周从 loops + 记忆里提炼 1–3 句，进 `insights`）；记忆分级参考 MemoryOS。
验收：反思句必须能追到具体记忆/loop；不许出现新事实。

## 十五、测试计划

### 单元（~60 项）

- `intent.js`：创建（合法/非法 source）、同源合并、due/过期、四种 kind 的 TTL、销账后不再 due、渲染最多 2 条、`parseShare` 拒绝空/没有/算了、排序稳定。
- `commitment.js`：句式表每一行（去睡/晚安/去忙/等我/回来再讲/明天说/我等你）、不在场时不进 asleep、十秒内说两次不重复、承诺对账（kept/missed）、早上自动醒、`away` 到期。
- `proactive.js`：`pokeGate` 新理由逐条；`parsePokeReply` 的 `speak/loopId` 合法性；空壳检测。
- `drives`：固定时钟断言（周一 10 点 / 凌晨 2 点 / 被晾 3 小时）。
- `fresh.js`：新块 TTL 必须存在（沿用现有抛错测试）。

### 集成（host.test.mjs，~20 项）

- 读一章（假后端）→ `intents.json` 出现 loop，`source` 正确；
- 他发消息 → `contextBlock` 含新块；不含过期 loop；
- 她说到了 loop 内容 → 下一轮不再出现；
- 主动通道：有 loop + 额度 → 模型回 `speak` → 发出 + `session.note` + 标记 → 第二天不再说同一条；
- 他刚回来（`lastUserAt > lastTryAt`）→ 不发；
- 她在 asleep → 等待型/有话说型都不发；
- 关掉 `intents.enabled` → 输出与现在逐字节一致（回归）。

### 反面测试（必须全过）

- loop 为空：她行为与现在完全一致（这条最难，也是回滚保险）。
- 一条被拒绝的开口不能把 loop 消耗掉（明天还能说）。
- 说过的话不进 loop；loop 里的字不进 system prompt 时不做消毒 → 测试必须抓出来（`<script>` / 长文本 / 换行注入）。

## 十六、风险、护栏与反例

| 风险 | 为什么会出现 | 护栏 |
|---|---|---|
| **播报化**：每天固定「我今天读了 X」 | 一旦「产生」变成任务，模型就会凑 | 产生点是她自己的反应调用（已经在写感想）；不想说就不写；`[想说:]` 可选；一条 loop 只说一次；过期就作废 |
| **假事件** | 模型为了显得有生活而编 | 每条 loop 必须有 `source` 且能核对；测试抽样校验；编的 loop 在面板上标红（M3 起） |
| **需求条游戏化** | 照搬心潮/AstrBot 的 0–100 驱动条 | 驱力只由真事算、只用于排序、不显示给用户、不进人格 |
| **主动消息变多、变烦** | 第二通道一开就超发 | 与等待型共用每日额度/冷却；发送前查「他刚回来没」；安静时段；空壳检测 |
| **承诺通货膨胀** | 模型爱说「回来给你讲」 | 规则只认明确句式；承诺到期要认账；连续 missed 会进人格证据；兑现率 <60% 就关掉承诺 |
| **她说了去睡却没睡** | 没有状态 | `rhythm` 状态机 + 主动通道跳过；他发消息时可以「被吵醒」，但不许主动开口 |
| **停机期间的生活被编** | 想让她「一直在」 | 明确不做：关机 = 不存在（`life.js:82`），`rhythm` 不写 |
| **重复说同一件事** | 没有销账 | `spokenAt` + 重复检测 + 测试「一条 loop 最多说一次」 |
| **和现有主动通道打架** | 两条路并行会一天找两次 | 并进 `decideIntent` 一个判定；共用额度；测试覆盖 |
| **成本**（虽然不管） | 多调用 | 产生并进已有调用（+0）；每轮注入（+0）；开口沿用已有调用；只有 M5 每天 +1 次 |

## 十七、回滚方案

1. **总开关**：`config.intents.enabled = false` → `refreshImpulse`/`readNovelIfBored`/`runGame` 不产出 loop，`contextBlock` 不加块，`decideIntent` 走旧路径，`processBatch` 不解析承诺。代码层面保留，行为与现在一致（集成测试断言）。
2. **分阶段合并**：M1、M2、M4 各自可单独 revert；数据文件独立（`intents.json`/`rhythm.json`），关掉即不再读写。
3. **数据迁移**：无（新文件，首次启动为空）。
4. **人格/记忆不受污染**：只有「说出口」的 loop 才进记忆（source:'said'）；关掉开关后不再产生新的。

## 十八、要拍板的问题

1. **「说去睡就真的不主动说话」，但他发消息时她要不要回？** 建议：回，但带「被吵醒」的语气；额度用一条。要不要更狠（真不回，第二天早上再说）？
2. **她说的话要不要能改关系/亏欠**（承诺没做到扣分）？建议：先只记 `sulk` 和记忆，不动关系，观察一周。
3. **她主动提起自己事的频率上限**？建议：与等待型共用每日 3 条；M2 先按 2 条/天跑一周再调。
4. **驱力要不要露出到面板**（只给你看 vs 只给日志）？建议：面板只显示「最冲的一股」一句话，不给数值。
5. **拒绝通道**：除了被戳时的 `[沉默]`，聊天里她能不能选择「这条不回」？建议：先不做（容易被当成故障），只做「晚点回」。
6. **M6 的记忆升级现在做还是先跑 M1–M5**？建议：先跑 M1–M2 一周，有了真实的 loops 数据，再决定记忆要不要动。
