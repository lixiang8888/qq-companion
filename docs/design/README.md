# 核心设计

> 这个目录放**这个项目的全部设计思想**：为什么是现在这个样子、哪些东西不能动、以及每一个看起来奇怪的选择背后的理由。
> 想知道「代码怎么写」，看具体文件；想知道「为什么这么写」，看这里。

---

## 一页纸

**她是一个只服务一个人的 QQ 私聊陪伴体，跑在 DeepSeek Harness 上。**

她不是助手、不是客服、不是角色扮演。她有一套**会随时间变化的状态**，一张**会模糊也会忘**的记忆，一个**一年只挪几步**的人格，和一点**自己的时间**——此刻在做什么、昨天怎么过的、以及刚才关机的那几个小时她不存在。

判断这套设计好不好，只有一条标准：

> **换一个语言、换一个宿主，她的行为应该还是同一个人。**

所以下面六个文档讲的都是**约束**，不是功能列表。

## 十条不变量（摘要）

完整版和理由在 [07](07-不变量·缺陷·取舍.md)。

1. 每一层状态都会回落，且回落只与时间有关——没人陪她的时候她也会慢慢好起来。
2. 只有**负向**的关系变化留下残留；善意记账，不复利。
3. 人格改变有三道闸（频率、跨度、幅度），且有回拉、有回滚。
4. 记忆有清晰度档位，按天下降，**离线按天补跑**。
5. 关于「他是谁」的记忆永不低于「清楚」，永不被数量淘汰。
6. 锚点（第一次相遇、他亲口要求记住的）永不被系统自己推翻。
7. 召回 = 相关性 × 重要度 × 清晰度 × 最近性，按预算截断。
8. **遗忘与失效是两件事**；失效必须显式、可见、可撤销、判定吝啬。
9. 三层叙事（日 / 周 / 月）由她本人写，系统只提供事实。
10. 进入她状态的每一个数字都必须能被外部核对；不能核对的，宁可不写。

## 开工前：先去 GitHub 看一眼

做任何新东西之前，**第一步固定是搜 GitHub**——DSH 插件、同类项目、以及「别人怎么接这个接口」。搜完再决定写不写。

- **有现成的**：先读 README 和关键源码，再决定是抄（借它的接口映射、错误码、坑）、装（借完整能力），还是只借它的坑。
- **没有现成的**：把「搜过、没有」写进 [references.md](../references.md)，别下次再搜一遍。
- 搜的范围至少要覆盖：DSH 插件生态、同宿主的其他项目、目标接口的官方/第三方客户端。
- 这不是省事，是省错。`qzone_*` 那套接口和五类错误码，是别人已经踩完的；自己从零摸只会重踩一遍。

## 维护约定

- 这里写的是**设计和理由**，不是实现。出现文件名、函数名时，只作为「这些东西住在哪」的指路牌。
- 文档里的数字（阈值、预算、基线）都是**当时的决定**。改了代码请回来改这里，否则这里会开始骗人。
- 新增设计先写在这里，再写代码。顺序反了，理由就永远补不上了。
