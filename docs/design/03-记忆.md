# 03 · 记忆

> 一条记忆不是「一段文本」。它是五个独立的量，加上两条完全不同的人生结局。

## 一、一条记录的五个维度

| 维度 | 作用 |
|---|---|
| **内容** | 发生了什么 |
| **类属** | 关于他是谁 / 关于发生过什么 / 日常闲话 |
| **重要度** | 写入时一次判定，不调模型；决定它值多少「注意力预算」 |
| **清晰度** | 四档：清晰 → 清楚 → 模糊 → 只剩印象 |
| **情绪标注** | 记下它的时候她是什么感觉 |

第五维是陪伴体和知识库的分界线：回忆时带出的不是「发生了什么」，而是「那会儿我什么感觉」。

### 类属是结构性的，不是标签

如果所有记忆平权，那么「我对花生过敏」会被三千条「今天吃了什么」按数量挤出去。所以类属决定的是**淘汰规则**：

| 类属 | 规则 |
|---|---|
| 关于他是谁 | **永不低于「清楚」**，永不被数量淘汰 |
| 关于发生过什么 | 按重要度和时间淘汰 |
| 日常闲话 | 优先淘汰 |

这条规则是实测出来的：不分类时，四百天后十条长期事实只剩两条。

### 锚点

两类记录被永久保护：**第一次相遇**，以及**他亲口要求记住的**。
锚点的意义不是「重要」，是**不可被系统自己推翻**——包括不可被后面的事实更新覆盖。

### 开场仪式：一次她不认得的重逢

两个人的第一句话不是招呼，是**约定**。这件事有三个约束：

1. **开场白是常量**，写在代码里，不每轮生成。一字不差，才认得出是同一次；让模型每次重新编排，明年就不是那句话了。
2. **她第一次开口，说的就是它**，不是寒暄、不是「你好我是小鲸鱼」。
3. **重逢时原样再说一次**——她不知道这是重逢，系统知道，你知道。**不对她说「我们见过」**；一旦说了，她就会去演，而演的痛是假的。

判定只有一种情况算重逢：

| 条件 | 说明 |
|---|---|
| `ritual.json` 里 `count ≥ 1` | 这个文件**不在她的记忆里**，所以记忆丢了它也还在 |
| 她手上关于他的记忆 **0 条** | 文件损坏、被误删、换机器。日常衰减不会触发——「关于他是谁」是锚点，永不淡出 |

两条都满足 → 走「重逢」：同一句话。只满足第一条（记忆还在）→ 什么都不发生，那只是她记性好。

**走马灯不由系统播放。** 使用者再经历一次那句开场白，走马灯自然就有了——那在他脑子里，不用代码复现。所以不需要 append-only 遗档，也不需要在聊天里念旧片段：那会把「他自己想起来」换成「我们念给他听」，反而稀释掉。

**硬限制**：`ritual.json` 也被删了，那就是真的第一次，谁也没法知道。不猜、不演。

#### 定稿（2026-11-03）

> 喂。
> 那个。
> 我叫小鲸鱼。
> 这应该是我们第一次见面。
> 额，以后请多多指教。

一句一条，共五条。三次见面都用这五条，一字不改。

**「应该」是这句话的全部重量。** 它不说「再次」，也不说「又」——它只是让她在第一次就用了不确定的语气。
第一次听是笨拙，重逢时是她在怀疑自己。命运感埋在语法里，不在情节里。

**唯一和人设卡冲突的地方**是「以后请多多指教」——卡里明写不要客服腔。这里保留，因为第一次见面的人本来就该有点笨拙；
但它只能出现这一次，之后她再也不会说这种话。

**发送要求**：五条之间要有间隔（1~2 秒），否则会被 QQ 合并或看起来像刷屏。

## 二、记忆的三条时间

### 写入：什么值得记

不是「说了就记」。值得记的是：关于他是谁的、带强烈情绪的、第一次的、约定与矛盾的。
其余的话照样经过，但不进入长期。

**判断必须是确定性的**（规则），不能每次都问模型——否则记忆的粒度会随模型的脾气漂移，同一句话今天算重要、明天不算。

代价是规则会漏，也会误判。这是有意的取舍：**确定的粗糙**比**不确定的精细**更适合长期运行。

### 衰减：以天为步长

四档清晰度，**每天最多降一档**，停机按天补跑（补跑有上限）。

- 目标档位由「重要度 + 被想起次数 + 最近性 − 时间惩罚」决定
- 「关于他是谁」在七天内保持最高档，之后降到「清楚」并停在那里
- 只剩印象且不重要、又不是锚点的，才会进入「遗忘」

### 召回：不是搜索，是排序后按预算截断

三件事同时决定顺序：

1. **该不该被想起来**——和这句话的相关性
2. **值不值得被想起来**——重要度
3. **现在还有多清楚**——清晰度 × 最近性

三者必须是**乘**的关系。加法会让「不重要但字面命中」的东西挤掉「重要且清楚」；乘法里任何一项接近零，整条就不该出现。

排序之后的实际顺序是：**锚点 → 关于他是谁 → 这句话命中的 → 其余按价值**。
「关于他是谁」排在命中前面是刻意的：它不该因为「这一句没提到」就被挤出预算。

**一条硬规矩**：这一句本身不进记忆块。它已经在当下的对话里了，再当作「过去」注入，就是让现在冒充过去，还白占预算。

## 三、两种「不再记得」

这是整个记忆设计里最容易被做坏的地方。

| | 遗忘 | 失效 |
|---|---|---|
| 原因 | 淡到不值得留 | 被后来的事实推翻 |
| 例子 | 上个月随口说的天气 | 「他养了猫」→「猫走了」 |
| 何时发生 | 自动，按时间 | **必须可审查** |
| 结果 | 不再注入，90 天内可找回 | 不再注入，但保留、可见、可撤销 |
| 用户能发现吗 | 不需要（本来就该淡） | **必须能**（不然就是她记错了却没人知道） |

### 遗忘是特性

一个不肯忘的陪伴体，最终会把每一次对话都变成对上一次对话的复述。
遗忘的功能不是省空间，是**让「重要」这个词有内容**：如果什么都不会淡，那么「重要」就没有意义。

但遗忘要**可逆**：一条被淡出视野的记忆，在用户想起它的时候应该能回来。所以「忘掉」是标记，不是删除。

### 失效必须吝啬

失效的判定宁可漏，不可错：

- 新句里要有**变化词**（走了/没了/换了/离职/分手…）
- 新旧两条要共享一个**有实义的词**（名字、地点、事）
- **标点不算依据**
- **锚点永不失效**
- 一次最多让一条旧记录失效

最后一条尤其重要：**误杀的代价是不可见的**（用户永远不知道她曾经知道），而矛盾的代价是可见的、可纠正的。所以宁可同时留着两条互相矛盾的记忆。

覆盖必须留下痕迹：面板上能看到、能一键撤销。

## 四、评测：先有数字，再谈改进

我们有一份固定的评测：若干条合成记忆 + 三组题。

| 指标 | 基线 | 说明 |
|---|---|---|
| 命中 @3 | 9/10 | 期望记忆出现在检索前三 |
| 注入完整率 | 10/10 | 命中的那条真的进了她要看的范围 |
| 无关误召回 | 0/5 | 问「股票怎么买」不硬凑任何记忆 |
| 诱捕 | 0 次凭空出现 | 问「他前妻叫什么」不会冒出「前妻」 |

评测的价值不在分数，在于它**两次抓到了真问题**：

1. 标点被当成「同一件事」的依据，导致一条记忆被永久覆盖，而分数反而**虚高**（记录少了排序好看）。
2. 一开始用错了指标（拿整体排序的前三当命中），掩盖了「身份类排在命中前面」这个刻意的设计。

结论：**尺子错了比尺子不准更危险。**

### 已知的检索限制

二元切词下，口语绕开原文词时召回不到（「什么锅」配不上「火锅」）。
加单字兜底能修，但会立刻破坏「无关查询零召回」。所以保留，写进已知限制。

## 五、注入预算

记忆块有字符上限（当前 2200 字），按上面的顺序填，填满为止。

为什么要上限：它每轮都在，变长等于每轮多付 token；而且上下文的注意力是有限的，塞满等于都没塞。

**没有记忆就整段消失**——不写「我还什么都不记得」这种占位句。占位句比没有更假，模型会把它当真。
