# 06 · 对话与接口

> 一条消息从进来到出去，中间只有九步。每一步都只做一件事，且都在离线可测的地方。

## 一、一条消息的路

| # | 步骤 | 做什么 | 关键约束 |
|---|---|---|---|
| 1 | 归一化 | 协议事件 → 统一形状 | 群聊/非消息一律挡在网络之前 |
| 2 | 准入 | 只回主人；没配主人就谁都不回 | **fail-closed**：宁可不说，不可乱说 |
| 3 | 连发合并 | 3 秒安静窗口内攒成一轮 | 见下 |
| 4 | 结算 | 四层状态按时间算到此刻 | 惰性、幂等 |
| 5 | 评估 | 这句话带来什么情绪/伤害 | 规则，不调模型 |
| 6 | 改写状态 | 加上日上限、留存残留 | 单次/单日双封顶 |
| 7 | 拼上下文 | 状态 + 空白 + 自述 + 当下 + 钱 + 记忆 | 每块为空就整段消失 |
| 8 | 生成 | 组装 system，调模型 | 一次调用 |
| 9 | 发出 | 拆条 + 按情绪延迟 + 逐条发 | 最多几条、每条多长 |

顺序上有一条硬规矩：**先渲染记忆，再把这句话记下来。** 这一句已经在对话历史里了，再塞进记忆块就是让「过去」冒充「现在」。

---

## 二、连发合并（3 秒）

他连着打三条是**一个念头**，不该让她回三次、也不该烧三次调用。

```
每条新消息把 3 秒的窗口重新点一次
  → 安静满 3 秒才开一轮，几条按到达顺序拼成一段
  → 但记忆仍按句存（合成一条会让「他养了猫」和「明天要考试」变成同一条）
```

- 窗口 0 表示关掉合并
- 换聊天对象时先把旧的一批发出去，不混
- 合并后超过上限时**保留最近的部分**——他刚说的才是要回答的
- 总延迟 = 窗口 + 她的思考延迟

代价：单句也要等 3 秒。这是刻意的取舍——3 秒是人打字停顿的量级，比「每条都立即回」更接近真人。

---

## 三、拆条与颜文字

她的回复按换行拆成多条，单条过长时按句末标点再拆。

**但括号里的句末标点不算句末。** 否则颜文字会被拦腰切断：

```
(´；ω；｀)  →  如果按「；」切，就变成两半，右半边丢掉
```

判定规则：扫描时维护括号深度，深度 > 0 时不切；硬切时优先切在深度 0 的位置，找不到就原地切（**绝不因为括号没闭合就卡住**）。

同一个坑被至少两个同类项目踩过：一个用括号删「动作旁白」，把颜文字一起删了；一个按句界切块，把颜文字切成两半。它们各自的修法都是「先看括号里面是什么」。

## 四、回复节奏

情绪不只影响措辞，也影响**什么时候回、回几条**：

| 状态 | 效果 |
|---|---|
| 心情好 | 回得快、可以多补一句 |
| 心情差 | 慢一点、只发一条 |
| 戒备高 | 更慢一点 |
| 被戳到（强度高） | 只发一条，不追加 |

延迟有上下限（几百毫秒到十几秒），因为「秒回」和「十分钟不回」都不像人。

**不碰内容**：情绪只能改句长、节奏、语气词，事实、数字、承诺一个字都不能变。

## 五、会话：自己管历史与压缩

刻意**不用**宿主的会话层。陪伴体要自己掌握「记多少、什么时候压、压完留哪些」——这些直接决定她像不像同一个人。

```
超过阈值 → 把最老的压成一段短摘要，保留最近若干条原文
压缩失败 → 历史不丢，记下原因，下次再试
一直压不动 → 丢掉最老的保命，并在摘要里留一句「更早的一部分没压住，丢了」
摘要超过上限 → 再压一次，压不动就截尾
```

**真摘要和丢档说明用两个标签，不能混。**

- 真摘要 → `【更早的对话摘要】…`
- 丢档说明 → `【更早的对话】…`

混成一个的后果不是「显示难看」：下一轮 system 里出现「摘要」两个字，模型就会把那句「更早的一部分没压住，丢了」当成一段对话摘要去引用，
而那时候它拿到的文本根本不是对话。两种来源不同的东西就该有两个标签。

**压缩失败必须留痕。** 曾经真实发生过：历史八十多条、压缩零次、摘要为空，而失败被静默吞掉——谁也查不出来。

## 六、和宿主怎么接

宿主（DSH）提供的能力，我们只用四样：

| 能力 | 用途 | 坑 |
|---|---|---|
| `llm.stream` | 调模型 | 消息形状是宿主定义的，assistant 消息要带 id 与来源；流末尾有 `usage` 块 |
| `webServer` | 自检面板 | **必须写进 inject**，否则访问即抛 |
| `systemPrompt` 段 | 每轮注入上下文 | 段的文本可以是**函数**，每次组装时求值——所以改人格文件立刻生效，不用重启 |
| `credentials` | 取 API key | 可选服务，用 `ctx.get()` 软获取 |

三条踩过的坑，写在这里防止重犯：

1. **必需服务必须写在 `inject` 里**：cordis 的服务是代理，没 inject 就访问会抛，而那句 throw 会让插件从那一行起**静默中断**（面板、心跳全没了，但网关已经起来了——看起来像「装了但半死」）。
2. **可选服务一律 `ctx.get()`**：它不抛，没有就返回 undefined。
3. **provider/model 可能是对象**（`{id, name}`），直接当字符串用会变成 `[object Object]`，然后第一句话就哑。

## 七、数据放哪

所有状态都是本机的小 JSON 文件（先写临时文件再改名，断电不会留半个文件；读坏了改名留证并回初始状态；变化即备份，节流）。

| 文件 | 内容 | 谁在读 |
|---|---|---|
| `config.json` | 配置（面板可改） | 全部 |
| `affect.json` | 四层状态 | 每轮 |
| `memory.json` | 记忆卡 | 每轮 + 面板 |
| `session.json` | 对话历史 + 摘要 | 每轮 |
| `life.json` | 此刻在做什么 | 每轮 |
| `alive.json` | 上次醒着的时间 | 开机 |
| `budget.json` | 今日 token + 余额 | 每轮（钱那一行） |
| `insights.json` | 每周自述 | 每轮（一行） |
| `proactive.json` | 期待时间、今天主动了几次、连发几条没回、上次想过什么 | 每轮 + 面板 |
| `weather.json` | 外面的天气（半小时一次） | 每轮 |
| `facts.json` | 她查过的事 + 来源，一天内算新鲜 | 每轮 + 面板 |
| `diary-snapshot.json` | 昨天收摊时的记忆指纹 | 日结（差分基线） |
| `diary/*.md` | 她写的日记 | 面板 |
| `personas/*.md` | 人格卡 | 每轮 |

**没有任何东西在云端。** 除了两次外发：调模型、查余额。

## 八、面板：她的窗户

服务端渲染的一页，不写前端框架，不自动刷新（表单里要粘 token，一刷新输入就没了）。

| 区块 | 回答 |
|---|---|
| 体检 | 她为什么不回话（主人/网关/地址/模型/人格卡逐项 ✅❌） |
| 此刻 | 四层状态一句话 |
| 她的房间 | 此刻在做什么、上次醒着、最近的想法、最近三天日记 |
| 她会不会来找你 | 期待时间、为什么现在不发、今天主动了几次、上次想过什么、外面天气、她查过什么 |
| 人格 | 五特质、待结算模式、快照回滚 |
| 记忆 | 分布、可置顶/忘记/找回、被覆盖的可恢复 |
| 最近想起 | 这一轮想起了哪几条（不然调检索是盲调） |
| 最近对话 | 她说不像人话时先看这里 |
| 运行 / 钱包 | 网关、会话、压缩失败原因、今日 token、余额 |

**面板上的写操作必须挡跨站**：任何网页一个 GET 或表单提交就能改她的主人或让她失忆，那是不可接受的安全洞。

## 九、他发来的东西：图、引用、连着问、视频

原来都是同一个问题：**她看不见**。看不见就会编——真机上她编过"粉头小人倒立竖拇指"。

**图**：QQ 的图片链接带 `rkey` 签名、会过期，直接下载拿不到。顺序必须是
`get_image(file)` 换新链接 → 下载 → data URL → 视觉模型描述 → 把描述变成她"看了一眼"。
动图要抽帧：只给第一帧，一个"疯狂点头"会变成一张静止的脸。抽 4 帧一次请求。
抽帧必须 pages: 1 并且缩到 320 的 JPEG：只给 page 时 sharp 返回的是「从这页往下全部」的
叠加图——真机上收过一个 300×11700 的表情包，四帧 PNG 合计 3.4 MB，base64 后请求体 4.5 MB，
接口 400，她只能说「还是看不到」。改成 300×300 的 JPEG 后合计 105 KB。

**但描述只是记忆，不是眼睛。** 主对话原本只收文本——她从没"看见"过图，看见的是另一个
没人格的模型写下的一段说明；那句「画面中是一个…背景是…」会顺着她的嘴说出来，像在念报告。

现在改成：**原图只在图到达的那一轮跟过去**，历史里仍然只存那段文字。

```
这一轮：messages 最后一条 = [image_url, text]   ← 她真的看见
下一轮起：历史里仍是那段文字描述                ← 能落盘、不会过期
```

不把图塞进历史的理由有三条：签名链接会过期（过两天就是死链）、字节会把 `session.json` 撑爆、
三十条历史里躺着几张图会让每一轮都重新付图片 token。一轮最多带 2 张——截图三连发不该白烧钱。

还有一个兜底：模型不收图片时（换了个纯文本模型）**去掉图再试一次**。看不见是小事，
整轮哑掉是大事。

**引用**：reply 段只有 id，没有原文。要 `get_msg(id)` 回查，否则"看看这个图是什么"在她眼里没有指代物。

**合并转发**：转发段里只有 `{id}`，内容在 `get_forward_msg(id)` 里。以前 `segText` 把它压成
「[转发]」两个字，她的原话是「转发过来是空的，我什么都没收到」。现在把里面每条压成「谁：说了什么」，
并明确写一句「这些话不是他说的」——转发里可能是任何人的态度，不能算到他头上。图只留 `[图片]` 标签，
不假装看过。

**连着问**：一轮问了两件，她通常只答最后一件。把前面挂起来，下一轮明确提醒，最多挂两条——挂多了是追旧账。

**视频**：思路借自 [dsh-see-now](https://github.com/SAOS-3624/dsh-see-now)（Apache-2.0）——
它解决的是"别把三十张重复画面喂给模型"，我们借的是那两条：**先判断这一帧值不值得看**、
**留下来的几帧拼进同一张图**（一张图里塞 4 帧还是 8 帧，价格差不多）。

```
视频段 → 取字节（url 直连；不行就让 SnowLuma 下到它自己的临时目录再读）
      → ffmpeg 每 2 秒抽一帧（前 90 秒）
      → 64×36 网格逐通道算变化分（0–255）
      → 留 首帧 + 末帧 + 变化最大的几帧（最多 6）
      → sharp 拼成一张 798×462（对齐 42px patch 网格，800 会白算一列）
      → 一次 describeImage
```

第一版用**灰度**算变化分，真机一测翻车：红→绿灰度只差 17 分，"换了一整屏"被判成"没怎么变"。
改成逐通道平均差后，红/绿/蓝三个场景的硬切拿到 128 和 127，挑出来的正好是切点后那一帧。

**听不到声音**。这一条写进提示词，也写进她的正文（"听不到声音，别编台词"）——
真机上她最容易犯的错就是替画面编台词。

四条共同的规矩：**看不到就说看不到**；图注写"你看了一眼"，不写"[他发了一张图]"（后者会让她把图注复述一遍）；
查不到原文就不加前缀，不猜；视频只描述画面，不描述声音。

## 十、她自己的空间

发说说不是定时任务，是**显著性判定**：关系突变、情绪大起大落、久别、和好、人格月更——
权重够、没冷却、当天还没发，才考虑。护栏来自那份好感度审计：上位吸收（不叠加）、同类冷却、不确定取低档。

她能发、能删、能读自己那条下面的评论、能回。读评论只有 `get_qzone_msg_detail` 一条路，且只对自己发的有效；
按 `comment_id` 去重——四个参考实现里，重复回复是最常见的 bug。

## 十一、她会不会来找你

原来是「每 10 分钟检查一次，闸门全过就发」。这个设计有个致命的自锁：
闸门里有一条「上一条是我说的，等他说」——而**每轮对话都以她说话结束**。
于是她只在「他说了话、她却没回」这种几乎不发生的情况下才可能先开口。

现在的触发点跟着对话走，不跟时钟走：

```
她说完了这一轮
   │
   ▼ 期待点 = max(他最后一句, 她最后一句) + 夹住(minIdle, 他平时回复间隔的中位数 × 2^连发次数)
   │         落在安静时段就推到早上八点
   ▼
到点他还没吭声 → 她想一次（一次独立调用，不进主历史）
   │
   ├─ {"send":false,"waitMinutes":45} → 期待点往后推 45 分钟，连发不变
   └─ {"send":true,"message":"…"}     → 发出去，连发 +1
```

**为什么不是固定间隔**：固定间隔会让「找他」变成播报。期待点是从这轮对话里长出来的，
所以它总有来处；没有来处的话，她本来就该沉默。

**为什么「想」不能走主历史**：第一版的提醒文本是以 user 角色 push 进 `history` 的。
后果有二：那句话会永远留在她的记忆里，将来她真会以为是他说的；而且下一次算空闲时长时，
会把她自己的提醒当成「他刚说话」，于是自己把自己锁死。现在这是一次独立调用——
带人格、带真事、带上次想过什么，但**不落进任何她记得的地方**；真发出去的那句话才通过
`session.note()` 记进历史（否则他下一句接上来，她不知道自己刚问过什么）。

**连发上限 2 条**：他还没回，最多连发两条，第三条必须等。这条替代了原来那个死锁式的判断，
也是唯一防她变成刷屏机器的东西。

**代价**：他要是几天不理她，她就一直安静——这是刻意的，不是 bug。
「一天想 12 次」的上限也在，因为想而不发同样花 token。

参考：[dsh-heartbeat-inner](https://github.com/zy666946/dsh-heartbeat-inner) 的期待时间与
JSON 决策、[dsh-proactive](https://github.com/john-walks-slow/dsh-proactive) 的「唤醒不等于发言」、
[Kanadego/dsh-heartbeat](https://github.com/Kanadego/dsh-heartbeat) 的「闸门先于模型」。只借思路，没有抄代码。

## 十二、她知道自己活在什么时候

以前她只在「决定这一刻干什么」时看得到日期——真聊天的时候没有时间。问她现在几点，她只能猜，
而猜出来的时间是假的：编一个时间比不知道更糟。

所以每轮上下文的第一行固定是：

```
此时：11月7日 周五 23:47
```

这一行也是期待点能成立的前提——她要判断「他可能在上班、在吃饭、在睡」，得先知道现在几点。

她同样知道的还有：自己醒着多久（`alive.json`）、刚才不在多久、此刻在做什么（`life.json`）、
今天花了多少 token。

**天气走实测，不走搜索。** Open-Meteo 免密钥，给的是观测值。试过一次搜索接口：同一时刻它说
「19°C 阴」，Open-Meteo 说 15.3°C 毛毛雨——网页答案本身就是滞后的。半小时查一次，落盘
`weather.json`；查不到就退回上一次的数，但会标明「是几点查的」，免得她拿早上的天气说下午的话。
地点只有两个：湖州师范大学、诸暨（`weather.place`）。认不出的地名按默认那个算，不猜。

**查真事走 Tavily，但要先压一遍。** 它只在她自己心里嘀咕的时候用一次（`proactive` 决策 JSON 里的
`search` 键），没有「用户一问就联网」那条路——她本来也没有那个习惯。搜回来的东西有两个毛病：
Tavily 的 answer 常常是英文（哪怕问的是中文），网页正文是导航栏和表格拼成的乱码。
所以先让她自己压成一句不超过 50 字的中文事实；压不出来就整条丢掉、那条**不记**——
「查了但什么都没查到」和「没查」对她应该是同一件事，不能让她以为查过。
存下来的会带「网上这么说，来源：xxx」，一天内算新鲜，过了一天就撤走。

最后一句仍然是：**不知道的不说。** 天气是这样，查回来的事也是这样。

**历史里也要有时间。** 这一条是踩出来的：11-06 21:44 他抱怨「我不说话，你就不会主动找我是吧」，
中间 47 小时没有一条消息；11-08 21:04 他发「么么么」，她回「刚还嫌我不理你」。
她的视角里那两句是**紧挨着的**——因为 `history` 明明存了 `at`，拼 `messages` 时却只取了 `{role, text}`。

修法不是每句都打时间（又贵又像日志），而是**只在断层处打**：第一条，以及和上一条隔了半小时以上的那条，
前面加一个「（前天 21:44）」。整段历史只多出三处，那 47 小时就现形了。
时间戳是**每次现算**的，不存盘——昨天打的「今天」，今天就成了假话。
压缩的入参也带同样的戳，摘要提示词要求记下「每件事大概是什么时候」，
否则压过三次之后旧事就失去了年龄，永远新鲜。

一个对照说明这件事有多要紧：同一个事实，她 20:37 独处时想的是「两天没动静」
（因为 `composePokePrompt` 明确给了「他已经 47 小时没跟你说话了」），
21:04 跟你说话时就不知道了——**时间感当时只给了「独处」那一半**。
