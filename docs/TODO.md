# 未做 / 待做清单

更新：2026-11-25 · 来源：意图层落地时用户拍板「第 6 项暂时不做，创建一个未做/待做清单」，
加上之前一直挂着的债。每条都写清楚「为什么没做」和「什么时候该做」，不写空话。

## 一、意图层留下的（2026-11-25 刚落地）

1. **M6 记忆升级（用户拍板：暂时不做）**
   计划书里的 M6：把 `loops` 并进记忆卡（`source:'intent'`）、Generative Agents 式「反思」层、
   MemoryOS 式分级记忆。前置条件：先跑 M1–M5 一周，有真实的 `intents.json` 数据再决定记忆要不要动。

2. **每日计划默认关着**
   `intents.dailyPlan: false`。它是这次唯一新增的高频模型调用（一天一次），所以默认关；
   开一周看产出质量，再决定要不要变成默认开。

3. **承诺兑现率需要一周数据**
   计划书里的验收线：兑现率 < 60% 就砍掉承诺功能。现在 `intents.json` 里 `promise` 的
   kept/missed 还没有一周样本；到 2026-12-02 左右统计一次，低就关掉 `parsePromise` 那条路。

4. **主动通道一个对不上的数（没查）**
   2026-11-25 的 `proactive.json`：`ticks.n = 2`（真的调了模型）但 `thinks.n = 7`（决定等）；
   按代码推是 5 次调用出错。当天日志没有留存，无法下结论——下次在 DSH 控制台留一份启动日志再看。

5. **真机验收还没做**
   计划书里的指标（主动提起自己生活 1–3 次/天、读完 48h 内提过 ≥30%、编造率 0、一条 loop 只说一次）
   都要等 DSH 重启（代码改了必须重启）之后跑一周才谈得上。当前是离线测试 784 项全过。

6. **`[不回]` 会让历史出现 user→user 的洞**
   她连续不回时，历史里会有他两句话中间没有她的回复。这是**真的**（她确实没说），但模型
   可能会把两句话当成同一轮来答。观察一周；如果出现「只答最后一句」的毛病，再决定要不要
   在下一轮注入一句「你上一条没回」。

7. **`ask` 类还没有产出点**
   账本支持「想知道、还没问/没查」，但现在没有地方产出它（搜索只走 `[查:]` 和主动通道）。
   等 M6 或搜索升级时再接。

8. **跨轮「冷处理」没做**
   现在只有单轮的 `[不回]`。真人会「我在生气，先不理你一会儿」——那需要一条跨轮状态
   （类似 rhythm 的 `sulk`），这次刻意没做（容易被当成故障）。

## 三、观察项（先不当 bug）

15. 联想一天 40 个、主动额度共用 2 条：「有话说」会不会把「想他」那条挤没。
16. 她说去睡之后他发消息：每次都被「吵醒回一句」，那个「装睡」的选择是不是形同虚设。
17. `detectSpoken` 靠连续 4 字重合销账，可能误销；一周后抽查 `spokenAt` 的记录。
18. 跨天目标一周没完成会重新派生（一天一次）；观察她会不会永远挂着一个「想做」。

## 四、这次改动的上线前提

**DSH 必须重启一次**：插件是 `link:` 安装，但宿主进程里还是旧代码（2026-11-25 21:37 起的进程）。

## 五、游戏平台化（2026-11-26 落地）

19. **真机验收没做**：重启后要看的真事——
    - `game.json` 自动从旧形状迁移（`library.pvz` 里还是她原来的关卡/最好成绩）；
    - 她真的会自己挑游戏（一次只有一款时也要能开局），一局结束浏览器进程必须退出；
    - PvZ 行为不变：关卡、暂停/收阳光、解锁植物、局后锚点、记忆、意图层都对；
    - 结构化游戏说出口的战绩（2048 分数、推箱子第几关）能对上 `game.json`；
    - 点灯走的是看屏兜底：材料里只有次数/她看到的话，不能出现具体关卡或分数。
    当前是离线测试 813 项全过 + `.tmp/smoke-games.mjs` 四款游戏真机冒烟通过。

20. **2048 在冒烟里连按时会丢键**：冒烟脚本把每手压到 120ms 时，5 手有时只进去 1~3 手（同样脚本跑第二遍正常）。
    真机上每手之间隔着一次模型调用（秒级），冒烟 400ms 一手时两遍都正常。观察一周；如果真机出现
    「她明明按了但盘没动」，在 `browser.key` 后核对一次存档变化，没变就补发一次。

21. **自主下载游戏没做（用户这轮拍板先平台化）**：
    下一步才是「她让 DSH 去 GitHub 找/下/自测一款新游戏」。已验过的通路：桌面版自带 Electron 当 node 跑
    `app.asar` 里的 dsh CLI，`--profile headless --help` 退出 0；真跑任务还差 headless profile 的凭据 patch
    和「只写她游戏工作区」的沙箱配置。不做的原因：先证明平台能接住新游戏，再谈让她自己找。

22. **单机 exe / 安装包不做**（用户拍板只浏览器游戏）：下载回来没法真操作、又有整台机器的风险。
    以后要开这个口子，必须先有隔离进程/沙箱和一次完整的安全评审。

23. **观察**：
    - 她自己会不会一直只玩一款（`pickGame` 按最久没玩的轮换，但她在挑游戏时可能总点同一个名字）；
    - 点灯每步一次看图调用，一局 40 步上限——看她会不会玩到一半就 `quit`（那是真实反应，不是 bug）；
    - 读书和游戏共用一次空闲时间：游戏一局 5~20 分钟，可能把当晚读书挤掉，一周后看比例。
